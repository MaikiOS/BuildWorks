# QA .168/.169: реальный результат и переход к ручной приёмке

12 октября2026 Ostrix прекратил работу над локальным модельным тестировщиком: время ушло на канал вместо результата продукта. Дальнейший игровой ввод/инференс не разрешён текущим этапом. Установлена QA0.19.169, повторная установка для [ручного списка](MANUAL_QA_169_RU.md) не требуется.

## Что изменено и доказано

- Реальный ответ .167 не содержал массива uiTargets, хотя объект CPU-теста содержал его. .168 использует DataContractJsonSerializer, тест проверяет опубликованные байты Reply/Respond, Unicode и путь. В Valheim массив появился.
- Первые32 native-контрола вытесняли BuildWorks. .169 ставит scoped-контролы первыми, сохраняя проверки raycast/перекрытия/ID и ограничения32/12000bytes. UI regression45; реальная игра подтвердила приоритет.
- UI-права требуют точного label, а не только имени общего Button. Проверки до/после inference используют тот же непрозрачный ID.
- Файловый критерий проверяет новое уникальное имя, непустой ID и точный набор prefab в store/export, SHA результата. До inference запрещены существующая целевая запись/файл и повторяющиеся критерии. Это не доказательство трансформаций, открытия редактора, стоимости, стройки или reload.
- CREATE_NO_WINDOW выдавал CP866 вместо ожидаемого UTF-8: Invoke-QAControl явно задаёт Console.OutputEncoding; regression запускает настоящий скрытый pwsh с русским текстом.
- Ollama отверг полный запрос9167tokens при6144context. Окно увеличено16384; тест проверяет бюджет запроса. Затем schema ответов ограничена текущими разрешёнными UI ID; text дополнительно требует focused/writable. Последнее изменение прошло CPU/обзор, реальной моделью в игре не проверено.
