# .190 — противоречивые данные креплений и предупреждение каталога

Внешнее крепление могло содержать полный native `itemData` и отдельные поля, например качество2 внутри пакета и качество3 снаружи. Конвертер перезаписывал снимок внешним значением. Теперь противоречивые свойства и custom data остаются неподдержанными данными с исходником; автоматического выбора одной версии нет. Совпадающие поля сохраняют исходные байты `itemData` точно. Это не включает наполненное строительство.

Независимое чтение выявило дополнительное расхождение: Valheim читает cheated bit как состояние предмета только начиная с110. Для109 байт прочитывается, но не применяется. Reader теперь отражает это правило; архивные байты109 не изменяются. Legacy без полного снимка с cheated=true кодируется110, чтобы не обещать несуществующее поведение109. Этот признак не предоставляет обычному игроку права восстановления.

Карточка каталога редактора теперь сохраняет вычисленную причину недоступности молотку вместе с предупреждениями preview. Открытие доступной модели в редакторе и штатный запрет строительства сохранены. Автоматическая замена старых prefab не введена: нужна проверенная таблица соответствий, а не догадка по имени.

## Доказательства и границы

- Geometry: воспроизведены исходная перезапись качества и расхождение109; после исправлений полный набор прошёл. Покрыты109/110, строковые/hashed ID, свойства/custom data, отказ без потребления полей и точность исходных байтов.
- Store: совпадающий snapshot и конфликт, сохранение неизвестного состояния и исходника после portable encode/decode/copy. Это проверка файлов, не восстановление в игре.
- Normal/QA build, HostContract, QA isolation и localization проходят; окончательные журналы находятся в `artifacts/host-1.0.20/*190*.log`.
- В targeted formatter три WHITESPACE в неизменённом блоке PrecisionPlacementSession (старые5535/5536 →5537/5538). Новая ветка warning не вызвала замечаний. Helper `verify` отсутствует; использованы прямое чтение, тесты и независимые проверки.
- Workbench использует заглушку Session и не проверяет native PieceTable. Игровая приёмка предупреждения ещё открыта: [готовый сценарий](MANUAL_QA_190_RU.md).
- UI предупреждает о неподдержанных данных в целом; отдельного объяснения каждого конфликтующего поля пока нет. Полные предметы/права/сеть/колышек/v11 и весь модуль не завершены.

Установка и SHA фиксируются отдельно в живом списке. Игровые IL-дампы остаются только локально и в Git не публикуются.
