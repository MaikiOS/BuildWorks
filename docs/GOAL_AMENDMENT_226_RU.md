# Точечные изменения цели после .226

18 октября 2026. Это текст для Ostrix, **не изменение objective через Goal API**.
Полностью переписывать цель не требуется: её обязательные требования сохраняются.
Сделанное и оставшееся отмечаются в [живом списке](LIVE_CHECKLIST_RU.md), а не удаляются из цели.

## 1. Раздел11: заменить требование запуска только через Modded

Автоматические игровые проверки выполнять через ValheimQA по действующим
AGENTS.md и ValheimQA/RUNBOOK_RU.md. Основной способ — подготовленный GABS с
исправленным ValAgentBridge в TerrainRamp-1.0-Test: допускается прямой фоновый
запуск с BepInEx именно этого профиля без повторного согласования каждого запуска
в рамках текущей задачи. Перед действиями проверять профиль, QA save root,
cloud и существующие QA-мир/персонажа; не прерывать игровую сессию Ostrix.
После проверки штатно сохранять/закрывать игру и восстанавливать мост.
Ручной запуск пользователем — через Thunderstore → Modded.
Это не разрешает сбросы, новую выдачу ресурсов, посторонние изменения мира,
другие профили, сетевые сессии или публикацию без соответствующего разрешения.
Успешный ответ команды не заменяет проверку состояния, расходов и сохранений.

## 2. Раздел10: уточнить границу EarthWorks

Текущий этап — самостоятельное строительство дома BuildWorks без подготовки
фундамента или рельефа. Подготовка земли появится позже, при подключении
EarthWorks; его отсутствие не блокирует строительство. При будущей совместной
работе подготовка планируется с самого начала под выбранный чертёж, используется
одна общая табличка и одно хранилище. BuildWorks отвечает за здание, EarthWorks —
исключительно за землю. Отмена здания не откатывает рельеф. Внешний вид,
действия, доступ и учёт общей таблички/хранилища согласовать отдельно.
Сейчас полноценную интеграцию терраформирования не начинать.

## 3. Раздел13: уточнить ближайшую очередь

После проверенного ограниченного этапа оплаченной достройки продолжить
подключение утверждённого v11 к незавершённым частям строительного проекта и
обычного пути размещения к сохраняемому проекту с табличкой. Проверить длинную
стену из четырёх последовательных секций с проходами с разных сторон, затем дом.
Далее довести безопасную отмену с возвратом только фактического вклада,
восстановление после сбоев и оставшиеся обязательные сценарии модуля.
Эта очередь не отменяет требований конвертации, редактора, предметов, прав,
библиотек, выделения, производительности и сетевой игры.

При проверке сохранности различать постоянные ID проекта/детали/операции и
сетевой ZDOID: Valheim может назначать последний заново при загрузке.
Находить результат по сохранённой однозначной связи с проектом и проверять
состав, трансформации, оплату и состояние; совпадения позиции или внешнего вида
недостаточно. Сбой/повтор не должен заново создавать или оплачивать часть.

Результаты .226 — четыре стены16/16 и world reload10/10 — записаны в отчёте,
а не превращены в утверждение о готовности всей цели.
