# .173 — журнал передачи до изменения инвентаря

2026-10-13. При фиксации кода .173 не была установлена; позже в этот день выполнена guarded установка QA .173. Версия/две SHA/158 неизменных config-файлов проверены. Актуальна [ручная очередь .173](MANUAL_QA_173_RU.md). Наполненные хранилища в игровом placement ещё запрещены. Журнал подключён к локальному primitive .172, но сам primitive пока не вызывается стройкой.

## Реализовано

`BlueprintStorageTransferJournal` создаёт отдельный файл операции через `CreateNew` и удерживает исключительный writer. Подготовка записывается и перечитывается до возврата готового transfer. Перед снятием экипировки/очереди и native Move записывается Attempt с `Flush(true)`; затем — фактические наблюдения и отдельное локальное завершение. Ошибка записи останавливает дальнейшие перемещения. Файл не удаляется/не перезаписывается ради повторного запуска.

В подготовке: GUID операции, мир, native player/creator, prefab/hash и имя объекта, новая идентичность target `ZDOID(UserID, ID)`, сетка, записи предоставленных вещей (prefab, source/target cell, исходные количества, raw snapshot и нормализованные собственные свойства), отдельно фактические строительные списания. `DescribePaid` отдаёт изолированные клоны ledger, не изменяя возврат и не связывая его с форматом журнала. UserKey не используется как постоянная идентичность.

В Attempt: фактические source cell/количество/raw snapshot/свойства, equip/queue, полные хеши состояния обоих инвентарей, native ZDO bytes hash, ZDO/cache revisions, свободная ячейка. В Observation: количества/присутствие/source object stack/cell, собственные свойства/хеши, revisions, native bool/ошибка, equip/queue до/после, локальный save flag. Writer и reader проверяют одинаковый контракт: успешная запись соответствует точному Attempt и изменившимся hashes, grid/flags/revisions согласованы.

Перед Attempt и повторно после unequip проверяются точный набор уже переданных вещей, отсутствие extras, совпадение cache/ZDO revision и live inventory с native s_items. Посторонний предмет в другой ячейке и устаревший контейнер не достигают native Move.

Формат имеет schema/version, GUID/sequence/kind, previous SHA256 и checksum каждой рамки. Reader ограничивает размер/число записей, проверяет порядок/идентичность/семантику и отличает оборванную рамку от допустимого незавершённого префикса. SHA обнаруживает повреждение, не является серверной подписью или защитой от владельца файла. Удалённый целиком хвост может выглядеть как остановленный префикс; он всё равно требует сверки.

Пределы:128 записей/элементов каталога,16MiB файл,4096 предметов. Полный консервативный объём всех records, повторяемых snapshots, bounded errors, UTF-8 имени и framing проверяется до `CreateNew`, а не после частичного переноса. Ошибка сообщения ограничена1024 символами. Если мод неожиданно увеличил свойства после mutation сверх зарезервированного места, Observation становится `Uncertain`: вместо увеличенного snapshot сохраняется явно помеченный SHA256; начальные свойства остаются полными в подготовке. Это не полное сохранение новых неожиданных атрибутов и не успешное восстановление.

Незавершённая запись удерживает связанный контейнер от обоих путей отмены даже при пустом инвентаре. Проверяются мир и resolved UserID/ID; неизвестный/повреждённый файл запрещает очистку. Старые сетевые ID не назначаются новому объекту. Перенос source ref через перезапуск не реализован: одинаковые stacks нельзя различить по одной позиции/свойствам.

## Доказательства

- Production journal/source + настоящий файловый ввод/вывод:36 assertions. Отдельный процесс прочитал файл без памяти writer; закрытый writer не позволяет повторно создать тот же GUID. Полный/оборванный reader, checksum/order/identity/размер, противоречивые success records,100×32KiB общий бюджет и near-limit ASCII/4096-CJK case проверены.
- Actual transfer на инертных native/capture services:162 assertions; резерв31. Включая ошибки журнала до/после native Move, сохранение InFlight без автоматического повтора, пустой target с unresolved record, extra/stale/raw target, oversized unexpected properties. Это не native Valheim execution.
- Две отрицательные копии отклонены: пропущенный write-ahead и пропущенный UTF-8 name budget. Чистые sources снова PASS; receipt хранит SHA placement/preview/transfer/capture/journal и false для native/game/recovery-enabled.
- Normal/QA builds0/0; весь Geometry suite с настоящим construction ledger/exported-clone checks прошёл; Host contract текущего Steam manifest25730771/SHA и localization990 прошли. Headless Unity compile/contact и actual capture/cancel acceptance прошли на конечных sources отдельно; визуалы не переснимались.
- Independent correctness PASSED; Ponytail Ship после исправления stale destination/противоречивых records/полного бюджета/UTF-8 имени. `verify` skill отсутствует: выполнены прямые проверки и независимое чтение. Логи `artifacts/checkpoint-0.19.173/`; извлечённые native исходники в Git не включаются.
- SocratiCode: parent Default index green28979, watcher active, без переиндексации; C# graph дал посторонние рёбра, связи проверены rg/source. MemPalace вернул прежний запрет наполненного placement и отсутствие server ack; вывод сверён с текущим кодом. Первая IO fixture обнаружила sharing conflict у File.ReadAllBytes, слишком длинный тестовый путь и недостающий catch InvalidDataException; fixture исправлена и повторена. Это не подтверждённые ошибки игрового UI.

## Что НЕ завершено и что дальше

Reader всегда возвращает `RequiresReconciliation=true`, даже после всех локальных observations. Нет автоматического rebind, повторного списания, выдачи, возврата или снятия unresolved guard. `Flush(true)` означает запрос файловой синхронизации журнала, а не подтверждение физического носителя/профиля персонажа/мирового save/сервера. Нет общей атомарной транзакции двух inventory.

Далее нужен исполнитель сверки/возврата: сравнить реальное состояние после перезапуска, сохранить неопределённость одинаковых stacks, возвращать только доказанно переданные собственные вещи, не дублировать native drops/строительную оплату. Нужны сохранение игрока/target, серверные полномочия/подтверждение и идемпотентное завершение, затем отдельный Container placement после оплаты, пауза/отмена/UI и полный игровой стенд. Постоянный проект/колышек и принятый v11 опираются на этот учёт, но ещё не реализованы.

Новой ручной серии хранилищ пока нет: пользователь не проверяет недоступную функцию. Игру/модель/сохранения не запускал и не менял. Последующая установка .173 зафиксирована отдельно в живом списке. Полная цель остаётся незавершённой.
