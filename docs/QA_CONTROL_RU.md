# Быстрый канал управления Valheim — QA0.19.146 (введён в .141)

Канал встроен в тестовую DLL BuildWorks. Он передаёт ограниченные последовательности
клавиатуры и мыши в Unity внутри настоящего Valheim и возвращает состояние/кадр.
Это не управление Windows и не запуск Valheim в Unity Editor. В обычной DLL этих
типов и зависимости Unity.InputSystem нет. Порты и сетевые службы не открываются.

Текущая QA .146 установлена, SHA сверены;154 текущих config/save файлов неизменны при установке. Код91b2c14: исправлены чтение ответов и ограниченный повтор публикации при Windows1175. Базовый игровой smoke проведён на .145; .146 после установки ещё не запускалась. [Доказательства и ограничения](QA_CHANNEL_SMOKE_2026-10-11_RU.md). Далее — [серия содержимого](QA_0.19.144_RU.md).


Текущий результат2026-10-11: на .146 подтверждены свежие кадр/мир/look/step/release и UI-клики; переход test-fixtures ломает Respond уничтоженным selected UI, readonly state после stop тоже не публикуется. .156 исправлена/проверена CPU, не установлена; игра оставлена открытой, стройка не начиналась. ## Первый запуск

1. В Thunderstore выбрать **TerrainRamp-1.0-Test → Modded**.
2. Загрузить только персонажа и локальный закрытый мир **BW_QA_43d3719a**.
   Дождаться появления персонажа; окно игры оставить на переднем плане.
3. Сообщить агенту «в QA-мире, можно проверять канал». Первые действия —
   состояние и кадр, короткий поворот камеры, короткий шаг и ещё один кадр.
   Никакой стройки до подтверждения соответствия кадра/мира/координат.

Если персонаж мёртв, загружается, телепортируется, включены debug/no-cost,
подключён другой игрок, сервер открыт или окно потеряло фокус, batch запрещён.
Неизвестный модуль интерфейса либо изменение его layout даёт отказ.

## Команды для агента

PowerShell7, рабочая папка `Default`:

```powershell
./BuildWorks/scripts/Invoke-QAControl.ps1 -Action state -Capture
./BuildWorks/scripts/Invoke-QAControl.ps1 -Action batch -StepsJson '[{"milliseconds":200,"lookX":100}]' -Capture
./BuildWorks/scripts/Invoke-QAControl.ps1 -Action batch -StepsJson '[{"milliseconds":200,"keys":["W"]}]' -Capture
./BuildWorks/scripts/Invoke-QAControl.ps1 -Stop
```

`state` не вводит команды. В ответе: версия сессии через session.json, ID,
статус, focus/ready, мир, координаты персонажа/камеры, выбранный UI,
активный модуль и размер кадра. Снимок `screenshot.png` до1280px по длинной стороне.
Читать нужно кадр, указанный в **свежем ответе этого ID**: старый файл не доказывает
успех новой операции. `completed` означает завершение последовательности ввода,
не доказательство строительства или списания ресурсов.

Шаг содержит `milliseconds`20..2000, `keys` (имена Unity KeyCode, например
`W`, `Space`, `Escape`, `Return`, `LeftShift`), `buttons` (1ЛКМ,2ПКМ,4СКМ),
`pointer`, `x/y`0..1 от нижнего левого угла игрового кадра, `lookX/lookY`
в пикселях/секунду, `scroll`−5..5, `text` до256символов. Неуказанные клавиши
и кнопки отпущены. `text` меняет только уже выбранное доступное TMP/UGUI поле;
не является общесистемной печатью или произвольным выполнением кода.

Для drag: шаг нажатия в начальной точке; следующий шаг с той же кнопкой и новой
точкой; следующий без кнопки. Положение интерполируется. Не более32шагов и10секунд
фактического ввода. Кадры перехода входят в этот предел; длинные сценарии делить
на короткие наблюдаемые операции. На конце последовательности доставляется
отпускание кнопок, затем временные устройства удаляются. Нормальное завершение
сохраняет выбранное текстовое поле между batch.

## Остановка и проверка безопасности

- Физическая **F12**, движение/кнопки настоящей мыши или клавиатуры, потеря
  фокуса и `-Stop` прерывают активную последовательность.
- Незавершённые жесты редактора/выделения отменяются; автоматическая стройка
  приостанавливается. Уже выполненные игровые действия не откатываются.
- Отмена UI отправляет pointerUp/endDrag с исходным контекстом, без click/drop;
  восстанавливает inputOverride и физические текущие устройства.
- Проверить отдельно: остановка при W, удержании кнопки/drag, мировом выделении
  и при потере фокуса. После остановки персонаж не идёт сам, рамка выделения
  закрыта, drag не продолжается, обычное управление работает.
- При timeout состояние **неизвестно**: прочитать response.json или остановить.
  Автоматически повторять команду нельзя — возможны двойные игровые действия.

## Границы

Файлы находятся только в
`TerrainRamp-1.0-Test/BepInEx/config/BuildWorks/qa-saves/43d3719a7ee649d184e26ef1daa441a3/qa-control`.
Каждая сессия получает новый nonce, каждый запрос одноразовый и просроченный
запрос не исполняется. Канал не вызывает выдачу предметов, телепорт, запись ZDO,
строительство или расход ресурсов напрямую: кнопки идут через существующий
игровой путь. Правила стоимости и серверных прав этим каналом не заменяются.

Он ускоряет игровые сценарии, но не заменяет отдельные reload/network проверки
и проверку физического переноса курсора через край окна: virtual Mouse может
не поддерживать native warp. Основные сохранения и другие моды не менялись.
Текущая установленная QA .146 содержит введённое в .142 исправление отказа пустых Container; [границы](EMPTY_CONTAINER_CHECKPOINT_2026-10-10_RU.md). Базовый smoke канала прошёл; проверки контейнеров и расширенного ввода остаются открыты.
