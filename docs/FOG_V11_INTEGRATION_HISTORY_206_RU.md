# v11: точки подключения к BuildWorks

Статус2026-10-08: визуальная основа принята владельцем; игровой перенос не выполнен.
Передача: artifacts/fog-ghost-study/wall-11/HANDOFF_BUILDWORKS_RU.md.
Проверены SHA архива, CRC105 entries и все57 live-файлов manifest; baseline не изменён.
MemPalace вернул прежний обзор текстур/UV, SocratiCode — текущие Session preview/
pause paths. Ни память, ни лабораторный PASS не доказывают игровой перенос.

## Существующие точки подключения

- PlacementGhostPreviewView.CreateVisualClone: безопасная геометрия и исходные
  текстуры из доступного prefab. Создаётся визуальная иерархия без collider/Piece/
  ZNetView. Материалы v11 должны быть собственными копиями; общие игровые материалы
  и source-prefab менять нельзя. Native17 baseScale и исправленный BakeMesh сохраняются.
- PlacementGhostPreviewView.Show: соответствие planIndex/visual пригодно для
  ограниченной проверки. Постоянному проекту нужны stable part IDs и подтверждённая
  маска незавершённых частей. hiddenIndex не является состоянием строительного задания.
- BlueprintBatchedPreview.Prepare/Draw: сохранить пакетный путь тяжёлых построек;
  отбирать незавершённые части до пакетирования. Разные области расчёта нельзя
  назначить через один общий MaterialPropertyBlock без явной принадлежности.
- PrecisionPlacementSession.CompleteNativePlacement/PauseAutomaticPlacement:
  только временная очередь, не постоянное задание. Finish/Clear убирают её визуал.
  Временный placementPlanIndex не заменяет серверное хранилище прогресса.
- Лабораторный FogGhostLab.OnPreCull/OnRenderImage связывает поверхность, уплотнение
  сетки и объёмный проход камеры. Одного shader или cginc недостаточно. Игровой
  адаптер должен согласовать камеру/depth/postprocessing и корректное освобождение.

## Ограничения и зависимые этапы

1. Host Unity6000.0.75f1 подтверждён UnityPlayer.dll; лаборатория6000.0.61f1 DX11.
   Совместимость shader/compute и asset loading проверить отдельно на реальном хосте.
   В текущем csproj нет готовой доставки этих shader/compute ресурсов.
2. v11 поддерживает одну стену/одну капсулу; Trail24 — история одного тела.
   SourceBin использует YZ32x32 без ID детали. Для нескольких стен/этажей нужна
   корректная принадлежность плотности; целый дом старой сцены07 не доказывает v11.
3. Десять96x80x80 ARGBHalf полей занимают46.875MiB без Texture3D/сеток/buffers.
   Не создавать их для каждой детали. Нужен измеренный бюджет общих/локальных областей.
   Evaluate содержит догоняющий while; reset/disable ждут GPU readback. Проверить
   скачки времени, задержки, паузу и выгрузку без зависания/утечки.
4. ID чертежей и stable IDs деталей уже есть. Не реализованы ID экземпляра задания,
   связь с неизменяемым снимком/версией чертежа, серверные состояния деталей и ссылки
   на созданные ZDO, колышек, серверные действия и устойчивое хранение/возврат оплаты. Клиентский туман только отображает будущий подтверждённый
   job-state; оплатой, правами и сохранениями эффект не распоряжается.

Первый этап: один renderer-only clone с v11 и реальным prefab, собственные материалы,
shader/compute capability и сравнение с замороженным роликом. Далее несколько
повёрнутых/масштабированных деталей, принадлежность тумана, адаптер тела игрока,
завершение/отмена/выгрузка и бюджет дома. Игровой job-view подключается после появления
надёжного состояния задания. Это план подключения, не утверждение об интеграции.

Лабораторный архив/извлечённые vanilla assets не распространять. Мод получает игровые
модели/текстуры из доступных prefab. Дополнение цели: GOAL_AMENDMENT_FOG_V11_RU.md.
