Предварительная проверка требует отсутствие прежнего fixture; если исход записи не определён до назначения ID, автоматическая отмена не угадывает ID.

## Следующее исправление и границы

Сам solver работает на GPU. CPU хранит вытесненные velocity-страницы из-за **нашего программного field-бюджета 98 304 000 байт**, а не аппаратного предела видеокарты. Для32 владельцев/32768 blocks/Spatial3D оценка с4 резидентами составляет97 423 684 байт; уже5 требуют102 338 884. Все32 наGPU без upload-текстуры требуют230 134 084 байт, то есть ещё132 710 400 относительно резерва4. С измеренным renderBytes это341 264 404 байт/325,5MiB учтённых буферов; модели, source textures, драйвер и прочая игра сюда не входят.

В существующем полностью резидентном пути `VelocityUpload` отсутствует, `TrySubmitSnapshot` не запрашивает velocity-readback: перенос CPU↔GPU ему не нужен. Сначала сравнить этот путь при явно проверенной ограниченной GPU-резервации; текущие safety guards не выключать. Малый4-owner контроль укладывается в прежний лимит, но не доказывает работу дома28. Изменение бюджета для дома потребует отдельного проверяемого кандидата; normal/установленная .241 остаются неизменными. Подкачка с прямым native readback — запасной путь при нехватке GPU-памяти, а не обязательная основа эффекта.

Для подкачки рассмотрен прямой GPU-readback в ограниченные постоянные native-буферы, без промежуточной managed-копии. Он должен сохранить прежнюю страницу до подтверждения owner/generation/sequence, точные данные upload, очереди, историю и безопасное завершение pending callbacks. Прежний managed-reuse .240 убирал выделение массивов, но оставлял копию; это разные изменения. В установленной Unity через reflection найдены `AsyncGPUReadback.RequestIntoNativeArray(ref NativeArray, Texture, mip, callback)` и `Texture3D.SetPixelData(NativeArray, mip, start)`; это проверка доступности API, не выполненный кандидат или доказанное ускорение. Нужны точный layout/upload oracle и проверки времени жизни буферов до подключения.

Параллельно рассмотрено пропускание заведомо нулевых matter-проходов с сохранением velocity: пока **не внедрять**. Требуется доказать отсутствие false negatives у `MightContact`; иначе можно скрыть настоящий контакт. Эта идея не заменяет измеренную проверку readback.

Сборка QA-библиотеки 0 warnings/errors; 6 Python-тестов прошли; независимый read-only обзор разрешил native-диагностику после исправления ownership cleanup. `verify` skill отсутствует. Обзор ponytail: используются прежний fixture, счётчики и библиотека; solver/контроллер не дублируются.
