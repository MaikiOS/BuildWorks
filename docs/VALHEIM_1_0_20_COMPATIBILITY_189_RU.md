# .189 — совместимость с Valheim 1.0.20

Steam обновил Valheim между проверкой/установкой .188 и следующим запуском: 1.0.17/build25730771 → 1.0.20/build25909357. QA .188 отказала до смены корня сохранений и установки Harmony-патчей. BuildWorks отключился, поэтому появились обычные списки миров/персонажей. Codex ничего не восстанавливал и не выполнял игровой ввод. Ostrix загрузил TerrainRamp_Lab, затем штатно вышел.

## Что проверено и изменено

- По текущему IL независимо проверены ранняя инициализация хранения, override корня, отключение cloud, пути World/PlayerProfile, локальная запись и резервные копии. Обновлены только проверенные fingerprints: assembly_valheim `94998885B103D6E5F5480123EAEE0A093E82AF2DDEEEE37536C15BF555F24F3A`, assembly_utils `771D59CBF3EF704007267E8EAF89AAC231C172B052BD93F9C273A18381BD6D59`. Изоляция остаётся отдельной QA-возможностью с ранним отказом на неподдерживаемом хосте.
- Чтение инвентаря принимает 106/109/110, предмета на креплении — 109/110. Native ItemData.Save сохранил точный прежний IL-хэш; новый envelope — 110. Исходные байты и версия сохраняются, в том числе при конвертации itemData; 111 не считается поддерживаемой.
- Readback поддерживает профили 46/47, префиксы Player.Save 33/34 и инвентари 109/110. SavePlayerToDisk отличается от закреплённого прежнего тела только номером 47. Для Player.Save проверен участок до инвентаря; оставшийся хвост остаётся непрозрачным и при свежем сохранении сравнивается целиком, полного Player.Load не обещаем.
- Для мира поддержаны маркеры 41/42. DB2, completion, metadata и mapping обязаны согласовываться. Каждый неизменяемый chunk проверяется отдельно как 41 или 42: native incremental save может оставить старый chunk41 в новом поколении42. ZDO.Save сохранил прежний IL-хэш. Формат43, несогласованные заголовки, повреждения, переполнения и отмена отвергаются. Чтение не является полным разбором DB2, загрузкой мира или разрешением завершить возврат.
- Native ItemData.Load применяет бит m_cheated только для110; в109 байт потребляется без восстановления флага. BuildWorks не запускает архивный ItemData.Load для выдачи старых свойств обычному игроку: используется предоставленный игроком предмет. Эта разница хоста зафиксирована, а не объявлена полной административной поддержкой.
