## Следующая очередь

1. **Ostrix проверяет основной путь:** автоматический мировой snap17/18 и Forest Hut — импорт → редактор → призрак → стройка → один reload. Это главный игровой критерий. При конкретном дефекте его исправление идёт прежде расширения модуля. Принятые случаи заново не нужны.
2. **Следующая реализация разработчика:** общий резерв ресурсов стоимости и собственных предметов для контейнеров/креплений. Затем передача в новый контейнер, сохранность свойств предоставленной вещи, проверка фактического результата и безопасный отказ/откат без потерь и дублей. Архивное состояние обычному игроку не выдаётся. Полная система пока отсутствует; одиночный тестовый меч не будет назван её завершением.
3. **После надёжного учёта:** постоянный строительный проект, колышек, внесение ресурсов, продолжение/отмена после выхода; подключение утверждённого v11 к незавершённым частям. Визуальную концепцию заново не разрабатывать.
4. **Оставшаяся очередь:** ArmorStand, серверный admin restore и цены мировых объектов, объёмное выделение/тяжёлая цепочка, полноценная сеть. Проверки сети нужны по мере реализации серверных операций, а не только в самом конце. EarthWorks остаётся отдельным будущим контрактом.

## Почему долго

Я слишком долго развивал и отлаживал QA-канал и локального модельного исполнителя. Он не прошёл полный импорт/стройку/reload, хотя отдельные проверки работали. Это ошибка приоритета: диагностика продвигалась быстрее пользовательского результата. Дробные задания и частые перезапуски усугубили задержку.

Есть и обязательная сложная часть: игра сама рассчитывает snap/контакт, поддерживает ownership и сохранение инвентаря. Нельзя ускорить реализацию бесплатной выдачей архивных вещей или небезопасным откатом. Но эта сложность не оправдывает продолжение работы над неэффективным тестировщиком.

Локальная модель исключена из текущей очереди. Следующий проверяемый результат — полноценная передача собственных вещей и рабочий путь внешнего дома, а не очередное улучшение QA-канала. Календарный срок и процент готовности не выдумываю; основные незавершённые блоки перечислены явно.

Цель API не менял: свежий `get_goal` вернул `blocked`, доступного resume нет. Установка и документы выполнены по прямому запросу Ostrix; обновление документа не выдаётся за изменение цели.
