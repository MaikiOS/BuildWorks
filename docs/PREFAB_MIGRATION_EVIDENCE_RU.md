# Замены устаревших prefab: фактическая база

2026-10-15. Установлена .190; этот этап добавляет измерение, а не включает автоматическую замену.

| Исходный ID | Предлагаемый актуальный ID | Происхождение соответствия | Проверено | Ещё не проверено |
|---|---|---|---|---|
| `wood_wall_roof` | `wood_wall_roof_a` | В текущем игровом prefab есть дочерняя метка `REPLACED BY wood_wall_roof_a`; в новом — `Replaces wood_wall_roof because of "same name and position" snapping issue` | Совпали 24 содержательных узла, включая записанные дочерние TRS, intrinsic scale, mesh vertices/normals/UV0/indices, общие material references, renderer enabled/shadows, LOD bindings, два BoxCollider и три snappoint | Полные native параметры стоимости/опоры/допуска, автоматический импорт с происхождением, строительство и reload именно автоматически преобразованной копии |

Это соответствие основано на содержимом текущих ресурсов, а не сходстве имён. Метки разработчика доказывают намерение замены, измерения — перечисленные свойства геометрии. Они не доказывают равенство всех игровых свойств. Ручная замена четырёх записей в Forest Hut уже прошла стройку и reload на .189; это отдельное доказательство [конкретного игрового случая](FOREST_HUT_NATIVE_QA_189_RU.md).

Стоимость, физический материал/contactOffset, все параметры WearNTear и административное состояние не входят в этот геометрический снимок. Поддержка skinned моделей намеренно не заявлена: probe отказывает. Изменение manifest/bundle требует нового измерения, старый успех не переносится автоматически.

## Следующее подключение к импорту

1. Проверить native строительные данные актуального prefab. Строительство использует его штатную цену, станции, допуск и правила устойчивости; замена не предоставляет права и не обещает старую цену.
2. Ввести явное правило с исходным/целевым ID, доказательствами и границами версии. Показывать список и количество замен до подтверждения импорта. Не менять исходный файл или существующий пользовательский чертёж молча.
3. Сохранять исходный ID и связь с исходной строкой рядом с эффективным ID. Текущий `CompositeBlueprintStore.ValidSources` требует совпадения prefab с исходной строкой: простое присваивание нового имени нарушит происхождение. Нельзя отключать эту проверку или переписывать архивный source text; нужны сериализуемая запись миграции и проверки roundtrip/копий/Undo.
4. Выполнить импорт → редактор → призрак → штатная оплаченная стройка → reload для автоматически преобразованного случая. Ручное принятие старых тестов при этом не отменяется.

Автоматическая миграция ещё не реализована. Других подтверждённых соответствий в этом этапе нет. Отсутствующие модовые детали по похожему имени не заменяются.
