# Подключение утверждённого v11

[English](FOG_V11_INTEGRATION.md) · [Доказанный статус](CURRENT_STATUS_RU.md) · [Этапы](ROADMAP_RU.md)

Исходники/QA.213 содержат собственный Linear shader/compute-пакет:3 assets/8 kernels. Утверждённый источник/архив v11 заморожен локально; извлечённые vanilla-материалы не распространяются. Игровые prefab/текстуры берутся из host.

Реализованы textured visual/source baking, деформация капсулой, независимые владельцы, компактные поля и общий GPU-атлас. .210 добавила точные общие временные поля:настоящий дом28 прошёл в обе стороны/остановку/выход, recovery0, пик87408640. Скорость объёма (до8 FPS)/полный вид крыши, несколько игроков и постоянная стройка открыты. [Точные доказательства .210](FOG_SCRATCH_210_RU.md).

Точки подключения:

- `BlueprintFogVisual/Source/Simulation/Channels/Volume/Atlas` владеют временными визуальными/расчётными данными. Атлас производный, оплатой и сохранённым состоянием не управляет.
- `PrecisionPlacementSession` ведёт native размещение и временную паузу; `BlueprintBatchedPreview` — обычный пакетный призрак. Индекс очереди/скрытое превью не являются постоянным состоянием частей.
- `BlueprintConstructionRefund` проверяет реальную оплату/удаление перед возвратом; `BlueprintStoragePersistence/TransferJournal` — отдельные доказательства инвентаря. Старый storage WAL не является журналом недостроя.
- Постоянному проекту нужны неизменяемый чертёж/ревизия/размещение, стабильные ID частей и записи завершения/созданных объектов, серверные продолжение/отмена, табличка и точный возврат после сбоев. Туман отображает это состояние и восстанавливается после reload/reconnect.

Сейчас: существующий Forest Hut (28) деталей, ограниченные контактные поля, узнаваемые материалы, проход/остановка/возврат, отсутствие взаимодействий/коллизий и замеры памяти/FPS. Невосстановленный туман каждого владельца сохраняется. Затем постоянный проект/табличка. Стена или загрузка shader не завершают эти этапы.

Утверждённый вид: узнаваемая форма/текстуры/светопропускание; тело слегка искажает и раздвигает поверхность светлым прозрачным туманом с завихрениями; отверстие держится внутри; после выхода туман и форма плавно возвращаются. Не заменять таймером исчезновения, щепками, плотным коричневым дымом или повторяющимися спрайтами. Оптимизация сохраняет эталон.

Исходная локальная передача — `artifacts/fog-ghost-study/wall-11/HANDOFF_BUILDWORKS_RU.md`, не публичная загрузка. [Первичный анализ](FOG_V11_INTEGRATION_HISTORY_206_RU.md) исторический, включая тогдашние допущения совместимости/памяти.

## Текущий результат

[.213: общая фаза шума](FOG_NOISE_FRAME_213_RU.md) проверена и установлена. Игровой маршрут .212 технически прошёл, но Ostrix отверг вид растворения/возврата и сообщил о торможении. Это не приёмка v11; native .213 ещё не проверена.

### Почему прежнее уменьшение поля не сохранило эффект

Unity-контроль использует одну и ту же исходную плотность, шум, seed, тело, путь, время и шаг voxel. В частной копии compute меняется только выражение поглощения у края. Полная контрольная копия совпадает с runtime по всем четырём полям и away/peak/state на12 кадрах. Рабочий shader и установленная .213 не изменены.

На tick165 объёмно-взвешенная сумма alpha дыма:

| Область хранения | Граница поглощения | Значение |
| --- | --- | --- |
| Полная | Полная | 1,025640 |
| Обрезанная | Обрезанная | 0,577369 |
| Полная | Обрезанная | 0,577870 |
| Обрезанная | Полная | 0,989743 |

Вывод для этого прохода: основное раннее влияние даёт преждевременное поглощение, а не только выход за поле. Простое отделение границы не решает всё: на tick240 остаток0,068365 вместо0,045331; отличаются поля поверхности и учёт возврата. Эта сумма — диагностическая величина, не доказательство физического сохранения массы.

Один ограниченный sweep расширял halo по тем же ячейкам. Все четыре варианта сохраняют spacing и фазу сетки:

| Grid | Дым tick165 | Максимальная разница поля surface tick165 | Поля8 одинаковых активных источников + один scratch, байт |
| --- | --- | --- | --- |
| 48×56×72 | 0,989743 | 0,164001 | 58834944 |

| 80×80×80 | 1,025927 | 0,053894 | 155648000 |

Близкая общая сумма скрывает локальные отличия. Строгое совпадение состояния найдено только у полного контроля; это инженерная проверка, а не утверждённый Ostrix визуальный допуск. Лимит полей98304000 байт не изменён. Оценка памяти выше — только гипотетические одинаковые grids, без atlas/исходников; это **не** проверка раскладки настоящих28 деталей и не доказательство невозможности любого другого padding.

### Следующий кандидат: отдельное состояние, общий рабочий набор

Разбор Astra подтвердил: смешивать независимые детали в одну симуляцию сейчас нельзя. `history.xyz / mass` хранит среднее исходное место; после смешения нельзя восстановить доли владельцев по ближайшей детали. Трёхмерная карта владельцев после смешения этого не исправит.

Производственная интеграция кандидата **ещё не реализована**:

- У каждого владельца остаются полная логическая область v11, время, принадлежность и плотное поле velocity: завихрения существуют и в пустых ячейках.
- Colour/origin/surface сохраняются без потерь блоками; отсутствовать может только блок, у которого все исходные half-биты равны0. Отрицательный ноль сохраняется. Перед шагом поля разворачиваются в один общий плотный рабочий набор; физические kernels и аппаратная фильтрация сначала остаются прежними.
- Статический RHalf atlas хранит исходную плотность всех деталей; отдельные smoke/surface RGBAHalf atlases — только активных и ещё не восстановившихся владельцев. Запись и привязка к материалам выполняются **до рисования геометрии**; `OnRenderImage` только читает опубликованное состояние. Стабильные slots/revision, gutters и повторное использование требуют отдельной проверки.

CPU выполнил текущий целочисленный `Layout` без Unity/GPU. Старый28-элементный fixture точно воспроизвёл126955800 байт. Его размеры дают консервативный верхний предел статической плотности14106200 байт; восемь гипотетических полных полей с gutters —84345856 байт. Сумма98452056 укладывается в128MiB. Прежняя общая18-byte раскладка28 полных полей требует минимум332111808 байт и отклонена. Это проверка **сохранённого fixture и гипотетических8 полей**, не admission текущего дома.

У симуляции общий9-texture набор занимает44236800 байт, восемь плотных velocity —39321600. До прежнего лимита остаётся14745600 на sparse blocks, карты, ledger и одновременно живые старые/новые поколения. Ниже проверен один восьмиканальный GPU-маршрут; остаток для настоящего дома **ещё не подтверждён**. Учитывать пики выделений и staging; не вводить epsilon/eviction ради прохождения. Хранить32 полных velocity или обещать постоянные8 активных владельцев нельзя.

Измерительный код `Assets/Editor/FogSparseStorageProbe.*` / `FogRuntimeSparseCheck.cs` / `FogSparseSharedProbe.cs` проверен наGPU. Он пропускает только блоки с нулевыми half-битами; physics kernels и плотное velocity неизменны. Фикстуры содержат63488 конечных half-шаблонов, отрицательный ноль/subnormal, пустые блоки и четыре отказа. Маршрут до360 ticks предусматривает1444 сравнения полей,1083 ledger и16 дополнительных CPU-сравнений; старое поколение сохраняется до успешного восстановления нового. Отчёт отдельно считает занятые блоки, одновременно живые поколения и гипотетические8 одинаковых владельцев. Это не admission дома и не производственная реализация общего рабочего набора.

GPU-опыт хранения и общего рабочего набора **прошёл**: одна полная стена —1444 сравнения полей/1083 ledger/16 CPU; восемь независимых состояний при чередовании порядка —11584/8688/16, включая финальное восстановление каждого после чужого шага. Проверены63488 конечных half-шаблонов, отрицательный ноль/subnormal и четыре отказа. Пик encoded одной стены970240 байт; учтённый пик восьми кандидатов92268592 из98304000, включая карты, ledger и старое/новое поколения. Это частный reflection-опыт с синхронными чтениями, **не игровой allocator/renderer и не проверка дома/FPS**; reference simulations, source/atlas и driver staging не входят в этот полевой счётчик. Следом — производственный жизненный цикл хранения и раздельные atlases до геометрии, пространственный возврат и дом. .213 и bundle неизменны; Valheim не запускался.

Локально: `artifacts/fog-sparse-213/shared/verification.json`, `sources.json`, `unity.log`; прежний single-owner опыт сохранён в `roundtrip`. `scripts/Test-FogSimulation.ps1 -SparseOnly` требует оба результата. Валидатор заново принял настоящий GPU-отчёт и отклонил57 повреждённых shared-вариантов; это проверка валидатора, не57 GPU-прогонов.

Синхронное чтение CPU с выделением буфера каждый tick допустимо только для измерительного опыта; его общее время не является GPU timing. После хранения — общий рабочий набор, sample/gutters/slot reuse, порядок камер/геометрии, повёрнутые детали, удаление владельца и дом; отдельно измерить все allocations/staging и GPU-время.

### CPU-контроль следующего шага

CPU-контроль подтверждений добавлен в `BlueprintFogSnapshotState`: owner/generation/sequence/tick/revision, запрет повторного шага и recovery до подтверждения, retire/поздние ответы и неопределённый readback. Прошли128 групп CPU-тестов, normal/QA сборки0/0 и независимые PASSED/Ship. Контроллер теперь проверен с настоящим v11 в частном GPU-стенде; игровой жизненный цикл, очередь входов и renderer остаются открыты. Установленная .213 не менялась.

После разбора Astra выбран общий фиксированный GPU-пул4³, две карты на владельца, staging ledger и асинхронный receipt. Резервировать весь запрос до изменения free stack; при отказе сохранить прежние encoded/velocity/ledger/clock/render slot. Ошибка readback после возможного commit не доказывает rollback: такой владелец блокируется до полного безопасного teardown пула. Простое опустошение GPU-очереди не даёт права повторно освобождать неизвестные blocks.

CPU-файл считает перечисленные логические ресурсы:8 владельцев/24860 blocks —98303700 байт; ещё один block превышает98304000. Округлённые24576 blocks —98157156, резерв146844 байта; driver/readback staging, source и atlas сюда не входят. Это расчёт схемы, **не реальные GPU allocations**. Тестовый CPU-oracle проверяет нехватку1 block, успешный commit и packing rollback, неизменность чужих блоков и1000 циклов без дублей/потерь. Ниже проверен малый кандидат GPU-ядер резервирования/commit; новый код ещё не заменяет прежний вычислительный путь. Локальная квитанция: `artifacts/fog-sparse-213/snapshot-verification.json`.

### GPU-кандидат фиксированного пула

Малый GPU-кандидат фиксированного пула прошёл `-ArenaOnly`:8 синтетических владельцев8×8×8,47 commit/3 ожидаемых отказа,15 полных сверок —480 точных сравнений полей и360 ledger, включая atlas gutters и уникальность блоков.17 ядер скомпилированы наCPU, C#0/0,71 повреждённый отчёт отклонён; независимые PASSED/Ship. Это **не полный v11, не production allocator/каденция callback и не дом/FPS**. Частный полный physics gate теперь прошёл; далее игровой scheduler и shader-потребители. Установленная .213 и bundle неизменны, Valheim не запускался.

`FogSparseArenaProbe.compute` / `FogRuntimeArenaCheck.cs` выделяют buffers один раз. GPU считает все три поля, проверяет запрос целиком и резервирует новые blocks до освобождения прежних. После проверки packing неизменные flags разрешают запись velocity, staging ledger и smoke/surface atlas; затем возвращаются старые blocks и пишется64-байтовый receipt. При отказе возвращается только резерв, прежние поля/velocity/ledger/atlas остаются. CPU-контроллер принимает owner/generation/sequence/tick/revision и переключает карту только после ответа. Повторный шаг до ответа запрещён; соседний владелец продолжает использовать общий staging.

Четыре чередующихся batch после начального проверяют8 владельцев без индивидуальной квоты. Нехватка ровно1 block, ошибка после packing иInf сохраняют старое состояние; pending-удаление и поздний receipt при повторном slot не повреждают соседей. Пустой snapshot возвращает старые blocks, рост другого владельца использует общую свободную память. Все карты/free IDs и все voxels двух atlas с gutters сверяются. Фикстуры намеренно делают uploads и блокирующие readback-проверки; это не скорость рабочего игрового цикла и не проверка переноса staging ledger через физические kernels.

Локально: `artifacts/fog-arena-213/verification.json`, `sources.json`, `unity.log`, `guard-verification.json`; hashes совпадают с исполнявшимися исходниками. Настоящие receipts Sparse/Noise/Domain приняты прежними ветвями валидатора;71 отрицательная проверка относится к CPU-валидатору отчёта, не к71 GPU-прогону. Игра/GPU после этого опыта не запускаются без нового свободного окна.

Source/anchor/admission проверяются отдельно по настоящим треугольникам и pivot: полную стену нельзя незаметно заменить compact bake или исправить общий масштаб. YZ ledger внутри детали остаётся отдельным обязательным исправлением; 3D вариант требует сохранения стенового oracle и проверки нормировки возврата. Sparse-хранение не устраняет дорогой owner-loop raymarch и само по себе не доказывает FPS. Крыша, native/приёмка и постоянная табличка остаются открытыми.

Локальный CPU proof: `artifacts/fog-full-domain-plan-213/Check-Layout.ps1` и `layout.json`. Позднее Ostrix явно разрешил новое свободное GPU-окно; результат полного physics gate приведён ниже. Рабочая .213 не менялась.

Локально: `artifacts/fog-boundary-213/sweep.json`, `sources.json`, `guard-verification.json`; девять повреждённых квитанций отклонены. Независимое чтение PASSED, отдельный Ponytail Ship; повторное чтение GPU убрано. Новых игровых тестов, правок ресурсов/сохранений и публичного релиза нет.

### Полная физика и публикация metadata: GPU gate

**Полный physics GPU gate прошёл:** настоящий v11, два владельца96×80×80, пакеты1–8 и дробное время;664 точных сравнения полей/498 ledger/28 atlas,239 commit/2 безопасных отказа,242 проверки64-byte metadata до CPU-подтверждения. Проверен zero-step metadata-only и запрет обновления pending-владельца. C#0/0,2 HLSL-ядра0/0,169 отрицательных CPU-фикстур и независимые PASSED/Ship. **Это частный стенд с ожиданием readback: shader-потребители, настоящие кадры callback, production память, дом и FPS не доказаны.** Runtime/QA .213 неизменны; Valheim не запускался.

`FogArenaPhysicsProbe.cs` использует существующий solver без изменения runtime. Через reflection три read-поля и ledger привязаны к общему набору; первоначальные owner velocity/ledger сохраняются отдельно до GPU commit. Prediction-текстура хранит read velocity только до `AdvanceVelocity`, затем используется штатно; следующая скорость копируется обратно после всех чтений. Полные карты требуют450 групп, ledger —16; маленькая синтетика эту передачу не доказывала.

Основной маршрут:360 ticks двумя владельцами,80 пакетов1–8,161 ожидаемый commit и injected packing-отказ; отдельный pool ёмкостью1 блок должен безопасно исчерпаться. Oracle обновляется только после подтверждённого commit. После отказа speculative input history не используется повторно. Каждая проверка сравнивает4 поля,3 ledger, clock, уникальность maps/free; шесть публикаций включают все gutters. Полученный GPU-результат664/498/28 подтверждён свежей квитанцией; всего239 commit/2 отказа.

Измерительный стенд блокирует на readback, использует reflection и дополнительные reference/source/atlas/конструкторские выделения; это не production memory admission и не live callback/render proof. 64-byte запись динамических metadata теперь публикуется условно после полей и до receipt; неизменные domain/bounds остаются привязанными к slot/generation. Shader-потребители ещё не подключены. CPU-сборка с Editor refs не устанавливается в игру.
