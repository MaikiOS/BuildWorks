# Стенд Ostrix для мирового снапинга

19.10.2026. Сохранить исходный стенд; не разбирать его после передачи файла.
Этот сценарий нужен для воспроизведения нестабильного автостыка, а не повторной приёмки уже проверенного расхода ресурсов.

## Что включить

Подойдут твои вертикальные, горизонтальные и диагональные балки. Полезно оставить рядом внешне одинаковые балки, которые поставлены с противоположным поворотом, и хотя бы одну деталь с нестандартным наклоном XYZ. Не обязательно строить всё заново: важнее сохранить именно место, где результат скачет.

Оставь вокруг место для обхода с двух сторон. Добавь необходимые опоры: после размещения копия не должна разрушаться из-за отсутствия контакта с землёй. Никаких дополнительных модов ради этого теста устанавливать не нужно.

## Сохранить

1. С молотком открой ПКМ → «ЧЕРТЕЖИ» → «ВЫБРАТЬ В МИРЕ».
2. Для небольшого стенда выбери «Режим: экранная рамка». ЛКМ выбирает детали или задаёт рамку, Ctrl исключает лишнее. Первая выбранная деталь задаёт оси сохранённого чертежа. Включи балки и опоры, исключи соседние строения.
3. Нажми «СОХРАНИТЬ». В мире исходные объекты остаются. Новая карточка получает имя «Группа N» и категорию «ПРОЧЕЕ».
4. Открой её действия → «ПЕРЕИМЕНОВАТЬ», укажи `Ostrix Snap Stand`. Если меняешь чертёж в редакторе, перед передачей нажми «СОХРАНИТЬ».

## Передать без конвертации

На карточке нажми «Поделиться» → «Открыть папку». Получится полный переносимый файл `<ID>.buildworks.json`; имя с ID нормально. Это сохранённая версия, без преобразования в чужой формат.

В тестовом профиле эти файлы находятся здесь:

```text
C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\TerrainRamp-1.0-Test\BepInEx\config\BuildWorks\share
```

Скопируй нужный файл сюда и сообщи его имя:

```text
C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\Default\BuildWorks\artifacts\user-snap-stand
```

Если создавал стенд в другом профиле, используй фактический путь из окна «Поделиться». Этот профиль я запускать или менять не буду; для проверки нужна переданная копия в QA-профиле.

## Если нужен именно экспорт

В действиях карточки: «Экспорт файла» → формат «BuildWorks JSON» → указанная выше папка `user-snap-stand` → имя `Ostrix-Snap-Stand` → «Экспорт файла» → обзор данных → «Подтвердить экспорт». Итог: `Ostrix-Snap-Stand.buildworks.json`. Не выбирай PlanBuild или другой сторонний формат для основного образца: его возможности уже, часть данных может не поместиться. Оригинал не перезаписывается.

Достаточно одного способа передачи — «Поделиться» либо экспорт. Основной список чертежей хранится в `BepInEx\config\BuildWorks\blueprints.json`; передавать или редактировать этот общий файл не требуется.

## Что написать вместе с файлом

- Какую деталь выбираешь в молотке и на какую балку наводишься.
- Включён ли F9, какой поворот выставлен, какие клавиши удерживаешь.
- Где ожидаешь соединение и что меняется без твоей команды: положение, поворот либо оба.

Если возможно, короткий ролик с наведением полезнее одиночного кадра. Сам файл сохраняет детали и трансформации, но не движение камеры и последовательность ввода. Точные значения углов называть необязательно.

## Что проверит Codex

Одинаковое наведение с обеих сторон, скрытые перевороты осей, обычный молоток и F9, ручной поворот, штатные/добавленные/пользовательские точки и точность совпадения пары. Сначала временные призраки без оплаты и постоянной стройки. Изолированная проверка обработчика не заменяет воспроизведение полного пути выбора в молотке.

Обычный автостык сохраняет выбранный поворот. Отдельный режим по удержанию должен добавлять наклон цели без скрытого разворота; его выбор осей и поведение на симметричных/диагональных балках ещё требуют проверки этим стендом. Наклон, встроенный в геометрию prefab, нельзя надёжно определить по одному лишь повороту его корня.
