# Отзыв Ostrix по установленной QA0.19.132

Источник — сообщение Ostrix и снимок редактора, 2026-10-10. Это игровое
наблюдение пользователя, не самостоятельный запуск агента.

- Масштаб по одной оси работает. Выход мышью за предел мешает подтверждению;
  поднять максимум с400% до1000%, фиксировать допустимый максимум/минимум.
- Добавить последовательный выбор двух осей для масштаба и перемещения:
  X затем Z означает XZ. Повтор оси и Local/World не должны конфликтовать.
- Исследовать непрерывную мышь как в Blender: край viewport не ограничивает
  действие; отмена, фокус и закрытие обязательно освобождают курсор.
- Соединение17/18 предварительно работает после выбора точек. Проверялись
  прежние импортированные карточки; окончательную приёмку больших наборов
  отложить. Не просить немедленно повторять этот же случай.
- Замена улучшилась, но совмещение неудобно. Требуется отдельное позиционирование
  своих деталей на missing с сохранением рамки и missing-записи. Удаление отдельно.
- Меню Space больше не перекрывается — принято в Valheim.
- Новый отзыв не подтверждает компактность фильтра, задержку импорта и legacy22.

## Сценарий позиционирования — реализован и установлен в .135, игра открыта

Выделить одну missing-запись и свои детали либо выбрать источник из каталога.
Действие «Позиционировать на отсутствующую» показывает предварительное совмещение,
затем применяет его одной операцией Undo. Missing остаётся видимой отдельной записью;
свои детали доступны для ручной доводки. Их размеры и взаимная раскладка сохраняются.
Удалять ориентир пользователь решает отдельно штатным удалением.

Для записанного локального bounding box совмещать центр объёма с центром объёма
выбранных деталей в согласованной ориентации. Начало координат prefab и центр
bounding box — разные точки. При неизвестном объёме совмещать только записанную
точку/ориентацию и явно говорить об ограничении. Форму отсутствующей модели
не восстанавливать догадкой, не растягивать замену автоматически.

## Две оси — реализованы и установлены .136, игра открыта

G/S → X → Z выбирает XZ; поддержаны XY/YZ и обратный порядок. Две кнопки
подсвечиваются. Число при движении применяется по каждой выбранной оси.
Отмена/Undo/Redo/границы/потеря фокуса проверены; [протокол](PAIRED_AXIS_CHECKPOINT_2026-10-10_RU.md).

## Непрерывная мышь — пока исследование

В реальных UnityEngine.InputLegacyModule.dll/CoreModule.dll установленного
Valheim подтверждён публичный Input.mousePositionDelta в пикселях. Публичного
Cursor warp нет. Mouse X/Y зависит от чувствительности и не заменяет raw pixels.
Физический drag с Locked возможен, но один такой путь не решит G/S и доступ
к кнопкам осей. Реализация ещё не начата.

Blender Continuous Grab переносит курсор внутри области; абсолютные планшеты
обрабатываются иначе. Источник: [Blender 5.0 Input](https://docs.blender.org/manual/en/5.0/editors/preferences/input.html).
У Blender также есть [Window.cursor_warp](https://docs.blender.org/api/5.3/bpy.types.Window.html).

Текущий ввод BuildWorks использует Unity Input.mousePosition и относительные
Mouse X/Y для полёта камеры. Точного публичного аналога warp в используемом
Cursor API не найдено. Confined оставляет упор в край; Locked позволяет
относительное движение, скрывая аппаратный курсор. Минимальный кандидат —
временный захват только во время transform drag и виртуальная экранная точка.
Это ещё не реализовано. Сначала проверить реальный доступный API, поддержку
кнопок осей/числового ввода, отпускание при Esc/commit/потере фокуса/закрытии.
Win32-перехват и глобальное удержание курсора не вводить.

Общие источники Unity: [Cursor.lockState](https://docs.unity3d.com/ScriptReference/Cursor-lockState.html),
[Input.GetAxis](https://docs.unity3d.com/ScriptReference/Input.GetAxis.html).
Исследование API не является проверкой управления в Valheim.

### Дополнение .137 — новый Input System

Предыдущее ограничение относилось к UnityEngine.Cursor. В установленном Valheim
найден Unity.InputSystem1.19 с Mouse.current/WarpCursorPosition. Код самой команды
проверен в DLL: WarpMousePositionCommand.Create → InputDevice.ExecuteCommand.
Адаптер использует тот же публичный путь, проверяя код результата, и не включает
другой backend, не добавляет зависимость в пакет и не использует Win32 hooks.
Реальный native/enabled/added Mouse и обратная доставка в legacy Input.mousePosition
пока не доказаны. Workbench подменяет только физический ввод, а не контроллер.

Сценарий .137: активный обычный drag либо G/R/S вне режима поверхности → край →
перенос к противоположному краю с сохранением логической позиции. Ctrl позволяет
дойти до панелей. Свободная поверхность, точки привязки и раскладка Array не
переносятся: это наведение на конкретное место, а не продолжение transform delta.
Перед подтверждением сохраняются прежние проверки диапазонов/перекоса.
Команда переноса может прийти позже: ожидание без повторных команд, затем
компенсация скачка. Esc/потеря фокуса отменяют; Enter/отпускание гизмы подтверждает
последний допустимый предпросмотр. Нет подтверждения250мс — отмена предпросмотра.
Нет backend/команда отклонена — нормальный курсор и числовой ввод остаются доступными,
показывается ограничение. Это защитный отказ, не заявленная поддержка без backend.

Источники: [Unity1.19 Mouse](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.19/api/UnityEngine.InputSystem.Mouse.html),
[Unity cursor warping](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.19/manual/Mouse.html#cursor-warping).
