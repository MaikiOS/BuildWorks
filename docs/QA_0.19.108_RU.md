# .108 — точечная проверка большого редактора

Только установленная QA .108, профиль TerrainRamp-1.0-Test → Modded,
существующие QA персонаж/мир BW_QA_43d3719a. Основные миры не используются.
Это проверка редактора; ресурсы и новые стенды не нужны. Форму CoffeeTable повторять не требуется.

Готовый авторский тестовый файл: `07-heavy-editor.blueprint`, имя в каталоге `QA108 Heavy`.
Полный путь для поля импорта:

```text
C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\Default\BuildWorks\tests\fixtures\player-exchange\07-heavy-editor.blueprint
```

В нём1025 записей:1024 стены и одна намеренно отсутствующая `missing_qa108`.
Размер отсутствующей модели неизвестен; её маркер не является точной моделью.
Строительство этого неполного файла должно быть недоступно.

1. Исходное состояние: QA мир загружен, редактор закрыт. Через каталог выбери
   «Импорт файла», вставь полный путь, выбери файл и «Подтвердить импорт».
   Ожидается отдельная карточка QA108 Heavy с1025 деталями и предупреждением.
   Ошибка: отказ только из-за512 деталей, пропавшие записи либо готовность к стройке
   при отсутствующей модели. Исходный файл не должен измениться.
2. Выбери «РЕДАКТИРОВАТЬ». Пока видна «Загрузка чертежа», нажми «Отмена»
   (либо Esc). Ожидается закрытие загрузки без частично открытого редактора
   и без новой сохранённой копии. Если загрузка успела завершиться, закрой редактор
   без сохранения и повтори; это не ошибка отмены.
3. Снова «РЕДАКТИРОВАТЬ», дождись завершения. Во время подготовки есть счётчик;
   редактирование недоступно. Прокрути дерево до конца: последняя отсутствующая
   запись остаётся отдельно доступной. Ошибка: обрезание дерева, потеря строк,
   управление миром сквозь окно или оставшееся окно прогресса после завершения.
4. Выбери missing_qa108, перемести гизмой вверх, выполни «Отменить»/«Повторить»,
   затем «СОХРАНИТЬ» под именем `QA108 Heavy edited`. Закрой и открой эту копию.
   Ожидается1025 записей, изменённая позиция маркера и прежнее положение стен.
   Ошибка: удаление отсутствующей детали, сброс трансформации либо изменение исходника.

Автоматически эти операции уже проверены в Unity Workbench. Здесь нужны только
различия настоящего Valheim: отзывчивость, ввод, освобождение сцены и отсутствие
новых ошибок в BepInEx/LogOutput.log. Это не проверка50000 деталей, строительства,
сетевой игры или сохранения построенного мира.
