# Полные сценарии для локальной модели — 2026-10-12

**Игровые испытания на паузе по просьбе Ostrix.** Подготовка ниже выполнена
офлайн: без модели, GPU, игрового ввода, установки DLL и изменения QA-сохранений.

Модель получает один сценарий целиком: цель, файлы с SHA-256, условия, зависимости,
контрольные точки, ожидаемый результат, обязательные доказательства и правила
остановки. Последующие действия выбирает сама по свежему наблюдению. Это не
запрограммированная последовательность нажатий и не серия команд Codex.

## Журнал и итог

Во время будущего полного выполнения обязательны `events.jsonl`, `status.json`,
`report.json`, кадры и `checkpoint-before-reload.json`. Точные поля описаны в
`logging` манифеста. До действия: цель контрольной точки, краткая причина решения,
команда и исходное состояние. После: native квитанция, фактическое состояние,
кадр, длительность, ссылки на данные и вывод. Неудачи не переписываются.

Каждая контрольная точка получает собственный результат. `completed` допустим
только при доказательстве всех обязательных точек. Нет данных — `unverified`;
нет функции/среды — `blocked`; ошибка — `failed`; вмешательство/пауза — `aborted`.
Reload требует двухфазный checkpoint и нового разрешённого подключения; смена
nonce сама по себе не разрешает старую очередь. Без разрешения пользователя
после паузы ни одно задание не запускается.

Для ресурсов нужны полные экземпляры предметов и ledger расходов/возврата,
для строительства — реальные prefab/transform/состояние объектов, для содержимого —
реально открытый native inventory сундука/крепления. Прочитанный JSON, превью и
квитанция ввода не заменяют эти доказательства.

## Что уже работает и что ещё мешает полному запуску

Существующий `Run-LocalQAMission.py` доказал только целое небольшое задание:
модель сама открывает/закрывает инвентарь, поворачивает камеру и завершает работу.
Два прохода16,312с и19,844с; поворот20,204°/20,074°, состав инвентаря не изменён.
Журнал каждого решения/команды/native результата уже пишется. Два прежних неверных
ответа модели остановлены до поворота и сохранены, а не скрыты.

**Полные сценарии подготовлены, но пока не исполнимы нынешним пилотом.** В исходниках
[.167](QA_MODEL_UI_167_RU.md) подключены ограниченные UI-цели/поля и журнал отправки;
они ещё не установлены и не проверены моделью в Valheim. Нужны страницы целей,
точные snapshots чертежа/объектов/предметов, учёт расходов, полный исполнитель,
проверка контрольных точек и переход через reload. Нельзя передать полный JSON
узкому пилоту и объявить успех по инвентарю/камере. Сборщик явно выдаёт
`readiness: blocked` и перечень недостающих возможностей для каждого сценария.
Подготовка файлов не является реализацией полного исполнителя или игровым тестом.

S09/S11 ждут также соответствующих функций продукта; S12 — отдельно разрешённых
сервера, второго клиента и сетевой оснастки. Закрытый Local guard не ослабляется.
Текущий запас FineWood/Nails исчерпан: будущая стройка требует заранее рассчитанного
отдельно разрешённого QA-набора, без ручной добычи и сброса квитанций.

Автоматически:3 CPU-теста пакета прошли; отдельно6 тестов mission и5 прежнего
пилота. Полный просмотр изменений/контрольная точка фиксируются в handoff.
`verify` отсутствует; это не заменено заявлением о его выполнении.
