# .158 — чтение старого содержимого сундуков

Код `16afb6291a3f0260a99c8d8b4a64e38ca331398d`, дата 2026-10-11.
**QA 0.19.158 установлена только в TerrainRamp-1.0-Test; игровая приёмка открыта.**
Игра закрыта, агент её не запускал. Guarded WhatIf/deploy прошли, обе DLL
совпадают по SHA, 155 существующих config/import/save файлов неизменны; Default чист.

## Что изменено

Подтверждённый Inventory106 читается отдельно от109. Сохраняются точные bytes,
float-прочность, позиции ячеек, количество/качество/вариант, создатель,
custom data, worldLevel и pickedUp/equipped. Custom data разобраны как строки,
но неизвестное поведение сторонних атрибутов не восстанавливается.
v106 не пересохраняется в109 и не округляется до сотых: `LegacyDurability`
содержит исходный float, `DurabilityHundredths` для106 отсутствует.

Адаптер действует только для Info-only `.blueprint`, связан с точной исходной
строкой и получает размеры настоящего prefab Container. Не угадывает размер
по имени или крайним предметам. Требуется единственный обычный корневой
Container с Piece, без default loot, wagon/autoDestroy и специальных компонентов.
Неизвестный тип, размер, версия, ZDO/chance либо повреждённый пакет остаются
инертными. Unity читается только на host thread; фоновые задачи получают снимки.
Путь подключён к каталогу, обзору/подтверждению импорта и редактору.

Существующий `valheim-container-v1` хранит самоверсионирующийся пакет106/109.
Store22/portable11 не изменены. **Сборки до .158 не читают новый typed106**;
это расширение reader, а не обещание обратной совместимости старой DLL.
BuildWorks и Geometry при установке заменяются проверенной парой.

Читаемое содержимое можно сохранить либо явно очистить в отдельной копии.
Оригинальный пакет и source text остаются. Пустое эффективное содержимое
проходит прежнюю проверку обычного контейнера. **Перенос содержимого, admin
restore и сетевое подтверждение этой правкой не реализованы**; непустая
стройка остаётся закрыта. Права, стоимость и списание ресурсов не расширены.
