# Формат чертежа и крупные постройки

[English](blueprint-format.md) | **Русский**

Текущие исходники **0.19.68**: Store v12 / переносимый v3 добавляют исходное содержимое и ссылки деталей на строки.
Для совместимых `.blueprint`/`.vbuild` формат + имя файла + точный UTF-8-текст (включая BOM/переводы строк)
сохраняются через save/reopen, обмен, вставку, дублирование и Undo/Redo.
Исходный архив/путь не сохраняется и не заявлен; одинаковые формат/имя/текст намеренно объединяются.
Текст не исполняется: до 8 MiB на источник / 64 источников / 24 MiB суммарно; индекс строк деталей ограничен.
v11/v2 читаются; новые поля под старой версией, изменённые хеши/неверные строки отвергаются атомарно.
Чужие info/ZDO/chance и неизвестные секции всё ещё блокируют импорт целиком: это не полная совместимость.

Предыдущие исходники **0.19.67**: выбор файлов/настройки вывода и постоянный результат реализованы в редакторе/молотке;
чужой абсолютный масштаб один раз пересчитывается по реальной базе prefab без уменьшения/частичной конвертации.
Действия с опорами в «Инструментах», не строках объектов. Перезагрузка/сеть мира не проверены.
Полное хранение чужих заголовков/данных и тяжёлые интерактивные сцены ещё не реализованы.
Шаг **0.19.62**: [хранение опор и оставшийся сценарий](blueprint-support-frames_RU.md).
Store v11 добавляет необязательные supports (stableId/name/position/rotation) и placementSupportId;
переносимый v2 сохраняет эти поля. v10/v1 читаются без опор и перезаписи исходника;
поля опор под старой версией отвергаются. Штатный перенос надписей сохранён.
На том шаге дерево/гизмы, поза размещения и хранение мира ещё не были реализованы.
Замеры и список остатка .57 ниже — историческая запись того шага.

## Требование Ostrix: конвертация чужой постройки без потерь (2026-10-06)

Чужие постройки из prefab переводим в наш формат без молчаливого удаления данных.
Сохраняем заголовки/автора/описание, точные трансформации, надписи, точки и данные объектов;
неподдержанные поля не исполняем, пока их поведение не подтверждено отдельным адаптером.
Сохранить байты оригинала — архивная сохранность, но не доказательство одинакового поведения
отредактированной постройки. Данные земли можно хранить как неисполняемые сведения исходника;
изменение земли остаётся вне задачи. Оригиналы не трогаем, неполную поддержку не называем полной.

PlanBuild сохраняет `piece.transform.localScale` и присваивает его копии напрямую:
[первичный Blueprint.cs](https://raw.githubusercontent.com/sirskunkalot/PlanBuild/master/PlanBuild/Blueprints/Blueprint.cs).
Мы храним множители исходного prefab. Адаптер .67 различает системы, получает положительные
масштабы корня prefab на потоке Unity и готовит атомарную кэшированную копию. Неединичные/малые
базы и чтение нашего экспорта проверены; зеркальные/неподдержанные базы блокируются.
Не уменьшаем большие детали общим коэффициентом и не обрезаем размер
наугад. Недостающие prefab должны оставаться узнаваемыми, без подмен. Неподдержанные
трансформации/данные блокируем, не удаляем.

Сценарий обмена: видимый выбор файла без обязательного знания путей, имя/папка вывода,
сведения о возможностях формата и постоянный результат. Наш экспорт — полный основной вариант;
чужому формату нельзя обещать опоры/группы/XYZ/надписи, которых он не хранит. Проверки:
точная конвертация без правок и чтение нашего экспорта, сохранность после редактирования,
недостающие моды, отмена/ошибки/совпадение имён без перезаписи, неизменность оригинала
и измеренные размеры настоящей геометрии в Unity/Valheim.

2026-10-05. Ostrix поручил поддержку крупных построек из prefab, надписей,
авторских точек и конвертации чужих строительных чертежей. Произвольные меши,
земля, изменение миров/сохранений в разрешение не входят.

## Кто делает и чем подтверждаем

### Дополнение цели: обычные предметы и оснащение держателей (2026-10-06)

Ostrix добавил предметы в ту же активную цель. В редакторе нужны обычные игровые предметы,
особенно крепление на горизонтальные/настенные подставки и оснащение стоек брони.
Свободный предмет предпросмотра и предмет на держателе отличаются от строительной детали.
Крепление хранит связь с конкретной деталью/слотом, следует её трансформации и сохраняется
при копировании, вставке, Undo, записи нашего формата и импорте/экспорте.
Храним идентификатор и поддерживаемые свойства (количество, качество, вариант, прочность,
сведения модов). Непроверенным полям не обещаем одинакового игрового поведения.
Неподдержанные сочетания предмета/держателя остаются узнаваемыми с причиной, без подмен/удаления.

В мире применяем проверенные штатные API предметов/держателей, правила ресурсов, владения,
разрешений и сети: чертёж — рецепт, а не дублирование предметов.
Проверки: выбор/крепление/снятие и Undo; точное чтение нашего/переносимого формата;
содержимое импортированной стойки; размещение, сохранение/перезагрузка, снятие без дубликатов,
удалённый клиент. Модовые предметы/держатели требуют проверки возможностей;
установка произвольного чужого кода не разрешена. Дополнение записано, не реализовано; цель активна.

| Этап | Ответственный | Проверка результата |
| --- | --- | --- |
| Формат и конвертация | Основной агент; blueprint_format_contract57 — независимое ревью | Точное сохранение/чтение, миграции, отказ без частичных данных, оригиналы нетронуты |
| Большой редактор | Основной агент; blueprint_render_audit57 — замеры/ревью | Настоящие Unity-замеры открытия, выбора, Undo, миниатюр, памяти и отмены |
| Таблички | Основной агент; помощник проверил актуальный Sign API | Данные у каждого шага размещения; штатный SetText, сохранение/перезагрузка, клиент |
| Авторские точки | Основной агент; помощник проверяет контракт | Создать/удалить/Undo, точные системы координат, точки на поставленных деталях, перезагрузка/сеть |
| Обычные предметы / содержимое держателей | Основной агент; ревью формата/штатных API | Связь с держателем/слотом, свойства, Undo/обмен, ресурсы/без дубликатов, перезагрузка/клиент |

Лимит потоков не позволил создать третьего агента: повторно использованы два
помощника для чтения и ревью. Связанные файлы изменяет только основной агент.
Тест кода не является доказательством размещения/сохранения/сети в Valheim.

## Первый шаг: исходники 0.19.57

Внутренняя библиотека **v10**: необязательные `Part.signText` и
`Blueprint.customSnapPoints`. Миграции 1–9 сохранены; новые поля у старых
документов отсутствуют. Неизвестные/дублированные поля JSON и будущие версии
блокируют запись, сохраняя оригинал. Атомарная запись остаётся.

Переносимый **v1** `.buildworks.json` — обычный JSON: `format=buildworks-blueprint`,
`version=1`, `requiredPrefabIds`, `blueprint`. Список prefab — отсортированные
уникальные ID реально используемых деталей, не догадки об именах модов.
Чертёж содержит поля v10: положения/повороты/масштабы, группы/ID, видимость,
блокировки, основную систему координат и настройки миниатюры. Проверяются
обязательные/неизвестные/повторные поля, строки, числа, граф, объём и глубина.
Наличие игровых деталей проверяется отдельно; автоматических замен нет.

`customSnapPoints` — **дополнительные** точки в локальных метрах всего чертежа.
`null` и `[]` означают отсутствие дополнительных точек и не отключают штатные
или вычисленные. Старый вызов обновления без поля сохраняет имеющийся список;
явный `[]` очищает его. Вычисленные `anchors` отдельны. Вставка преобразует
точки через положение/поворот вставленной группы; Undo возвращает данные.
Создание в интерфейсе, привязка к детали и постоянные точки в мире ещё не готовы.

Текст до 4096 символов: CR/LF/tab и разметка сохраняются, другие управляющие
символы отклоняются. Надпись переносится через копию/массив/контур/вставку/Undo
и Controller/Store. Чужое произвольное `info`/ZDO не объявляется текстом:
поддержка требует проверки prefab и штатного применения после размещения.

Читаются точные конечные XYZ `#SnapPoints` и `.buildworks.json`. Отдельная копия
переназначает ID групп/деталей/опор и сохраняет новые поля. ID внешнего источника
зависит от пути и содержимого: экспорт и оригинал не смешивают кэш.
Архив не распаковывается, не исполняется, не перезаписывается и не распространяется.

Границы хранения: **50000 деталей/документ**, **100000/библиотека**, по-прежнему
32 своих чертежа / 12 категорий. Переносимый файл — 32 MiB, своя библиотека —
128 MiB, чужой текстовый файл — 8 MiB, суммарное чтение внешних файлов — 128 MiB.
Это защитные границы, не доказанная игровая ёмкость. Текущий синхронный
**бюджет предпросмотра — 512**. Все пути правки/размещения/миниатюр/просмотра
защищены; крупные документы не обрезаются, но огромная сцена одним кадром не
создаётся. Размещение с надписями/авторскими точками временно явно блокируется,
пока перенос в мир не реализован, вместо молчаливой потери поведения.

## CPU-замеры — не FPS и не отрисовка

GeometryTests `--benchmark N`, StoreTests `--benchmark N`. Одна машина,
включая начальную загрузку; живые managed bytes — не максимум/объём выделений.
Геометрия усреднена по 20 проходам, обмен — один полный цикл.

| Деталей | Открытие документа, мс | Видимость/блокировки всех деталей, мс | Перемещение→Undo→Redo→Undo, мс |
| ---: | ---: | ---: | ---: |
| 128 | 2,029 | 0,036 | 0,791 |
| 1000 | 2,825 | 0,486 | 5,921 |
| 5000 | 6,478 | 0,784 | 10,401 |
| 39487 | 41,142 | 2,648 | 50,912 |

Переносимый тест 39487 деталей: 8305976 байт; запись 283,280 мс; строгая
проверка/чтение 449,134 мс. Количество и последняя деталь сохранены точно.
Индексы ID убирают повторные линейные поиски и сбрасываются при Undo с тем же
числом деталей. Количество массива проверяется в 64 битах. Выбор меша
пропускает заведомо дальний объект до проверки треугольников; отверстия/закрытие
объектов проверяются прежними тестами. Бинарного контейнера мешей, instancing,
кэша блоков или монолитной постройки в мире пока нет.

96 совместимых / 257 блокированных из 353), локализация (751 ключ), EditorBridge,

лишнего каркаса нет; обход бюджета через прямой просмотр исправлен.
Свежий Unity-стенд: 144 состояния PASS, 2026-10-05T20:55:27Z, gameHostTested=false.
`dotnet format --verify-no-changes` возвращает 0, но сообщает предупреждения загрузки
workspace; компиляцию подтверждают настоящая сборка и перечисленные тесты.
verify не установлен. Установки, запуска Valheim и проверки миров/сети не было.

1. Захват надписей и применение **после** успешного штатного размещения; данные
   у каждого шага, не по текущему индексу массива чертежа. Проверки игры остаются.
2. Создание/удаление точек с деталью-владельцем, точное восстановление на настоящих
   деталях мира после загрузки, повторного соединения и у удалённого клиента.
3. Порционное отменяемое открытие больших сцен и ускорение по Unity-замерам.
   Документ — источник истины, мировые детали остаются отдельными.
4. Действия экспорта/импорта в каталоге и молоте, зависимости, настоящие тяжёлые
   чертежи. Тест конвертера не означает готовую кнопку интерфейса.
5. Одна понятная игровая серия после готовности этих сценариев. Стенд и статические
   проверки не заменяют сохранение/загрузку и сеть.

Разработка остаётся активной. Установленная .56 не меняется без отдельно проверенной
установки; исходники .57 — не завершённый релиз тяжёлых моделей.
