# Дорожная карта развития BuildWorks

[English](ROADMAP.md) | **Русский**

Обновлено 2026-09-30. Ostrix утвердил порядок после анализа развития.
Цель — предсказуемое строительство настоящими деталями Valheim, затем операции
групп и редактируемые генераторы. Этап заканчивается рабочим сценарием, не кнопкой
или математическим helper.

## База и доказательства

Кандидат в исходниках: **0.19.40**, Store v9, Valheim 1.0.16.
Ответ Ostrix по 0.19.39 подтверждает подсветку меню, смену языка и центровку.
Выбор с гизмой предварительно принят. Контур и подсказки требуют точечной
игровой проверки 0.19.40.
Все установки, обновления и игровые тесты — **только `TerrainRamp-1.0-Test`**.
`Default/BuildWorks` — исходники/артефакты, не установленный мод. Другие профили,
моды и saves не изменяются побочно.

Уже есть: индексный молоток/native favorites; отдельный редактор; числовые
трансформации, масштаб 1–400%, вложенные группы, независимые опоры групп/чертежа;
Array/Contour, Undo/Redo, контекстные подсказки; Q/E, preview целей 2 м и магнит
0,55 м; последовательное native размещение и отмена. Заменители missing prefab
тоже существуют.

Release, Geometry, Store, EditorBridge, WorldLayout, локализация и HostContract
прошли 2026-09-29. Это не текущая игровая приёмка. Прежние English/QE и короткий
запуск 0.19.38 в другом профиле — исторические доказательства. Специальный профиль
требует собственной серии. Актуальный результат — HANDOFF и
[текущий проход](../specs/roadmap/current-pass_RU.md).

## Правила статусов

Запланировано → В работе → Проверено автоматически → Ожидает Ostrix → Принято.
Регрессия переоткрывает затронутую проверку. Записывать дату, commit, игру,
профиль, хеши DLL и непроверенное. Сборка/скриншот не закрывают русский UI,
save/reload и сеть. Активен один ограниченный этап; зависимые изменения ждут
приёмки, отдельная подготовка может продолжаться.

## BW-00 Закрепить базу

Один target установки и проверка отказа остальных. HostContract использует
BepInEx/камеру специального профиля. Синхронизировать существующий source-only
checkout. Собрать/проверить/установить пару DLL только при закрытой игре.

Серия Ostrix: молоток/избранное; меню/ввод редактора; контакты стены/скоса/крыши/
мебели; Q/E сверху/снизу сетки; свежий Array/Contour; независимые опоры; Esc/
ресурсы; save/reopen редактора, reload мира; камера возле земли/выход; English/
Russian. Сеть принимается отдельно до новых world/network-путей, но не блокирует
подготовку макета изолированного UI. Проверить missing/unsupported детали и причины
блокировки; сохранять данные заменителей. Полный manifest — BW-05.

## BW-01 Сделать управление понятным

Последний ответ Ostrix подтверждает Q/E мебели, соседние точки, установку снизу,
опоры групп, Array, сохранение двух деталей, загрузку мира и камеру у земли.
Esc удаляет частично построенное и возвращает тот же призрак, но ресурсы выпадают
на землю; точный расход/возврат ещё требует подсчёта. Сохранение одной детали
пока намеренно запрещено действующим контрактом чертежа минимум из двух деталей.

Следующее согласование UI: явный выбор категории (переключение единственной
выглядит бездействием); общие ресурсы и станки в штатной панели детали вместо
окна «Ресурсы»; настройки сочетаний по режимам с переназначением; двойной клик
в дереве для центровки при сохранении F. Не прыгать камерой после каждой установки.
0.19.40 показывает линию контура при наведении; только клик создаёт призраки.
Очистка при отмене и расширенные подсказки ожидают игровой приёмки.
Ostrix согласовал просвечивание перекрывающих деталей: в 0.19.40 есть кнопка
у вьюпорта и F7. Выключено по умолчанию, только редактор, без изменения скрытия,
сохранённого чертежа или материалов мира. Проверяются выборочные лучи по mesh,
не каждый пиксель; прозрачные детали становятся окрашенными силуэтами,
выбор мышью не меняется.
Пользовательские переводы требуют описанного
формата файлов и тестов запасного языка/перезагрузки до выпуска.

До видимых правок согласовать небольшой макет UI/иконок. Разделить опору
размещения, центр трансформации, оси и исходную/целевую snap-точку. Select с
редактируемым выбором сохраняет числовые поля; множество явно показывает Δ.
Внизу — действие/состояние и доступные клавиши.

Явно выбрать фиксированную Y=0 или рабочую плоскость. Подложка не выглядит как
изменение координат документа. Активная snap-цель видна и при более чем 24
кандидатах; preview 2 м не меняет захват 0,55 м. Origin prefab не менять вслепую.

Приёмка: UI-клик не строит, текст получает клавиши, меню живёт нужный жест;
гизма/числа согласованы; детали ниже сетки доступны/видимы; EN/RU помещаются
при поддерживаемых масштабах. Использовать текущие View/математику. Компактный
F9 — здесь, не в конце карты.

## BW-02 Редактировать раскладку без изменения размеров

Раздельно: одинаковый локальный сдвиг элементов, радиальное смещение на заданное
расстояние, масштабирование только расположения. Каждая деталь либо каждая
непосредственная дочерняя сборка целиком. Выбор по prefab/детям/группе, инверсия;
Align min/center/max, Distribute, зеркальная копия.

Приёмка: четыре балки внутрь без изменения геометрии; нужные вращения и внутренние
расстояния сборок сохраняются; меняются нужные узлы; preview/cancel/apply и один
Undo. Общий recipe-framework и смена Store не нужны этим прямым командам.

## BW-03 Сохранить Array и вернуться к параметрам

Использовать нынешнюю математику. Только поля первого recipe: исходное поддерево,
параметры, устойчивые IDs, связь опор, явный Bake.
[Контракт recipes](../specs/spec-pattern-recipes.md) задаёт безопасность, не
обязательство сразу реализовать все будущие операции.

Приёмка: число/шаг после reopen, без drift/потерь; preview=commit=Bake; история/
порядок где поддержаны; безопасная миграция v9; неизвестные recipes сохраняются
либо блокируются, не удаляются молча.

## BW-04 Обсудить направляющие до кода

Сначала согласовать с Ostrix: магнитные позиции ручной стройки, повтор группы
или оба пути; редактирование точек, шаг/число, ориентация/крен, источник/центр,
открытый/замкнутый путь и сохранение. **Включая Line A/B.**

После согласования: Line A/B → polyline → arc → Bezier. Каждый срез сохраняется,
редактируется и отменяется. Математические тесты не утверждают инструмент.
Обычные детали не деформируются. Оригинальная адаптивная геометрия требует
позднего mesh/UV/collider/snap/network-контракта. Contour переносится на общий
evaluator после доказательства его работы.

## BW-05 Обмен без потерь

Версионный import/export, зависимости, причины готовности/блокировки, коллизии
IDs, missing recovery, transforms/groups/anchors/metadata. Неизвестный вход
не перезаписывает корректный документ. Без автоустановки модов и извлечения
чужих meshes/textures.

## BW-06 Расширение по необходимости

Linked instances и явный Make Unique; оригинальные детали/материалы; затем
отдельный terrain-мод, без скрытой правки земли. Сейчас не нужны node graph,
expressions, полный Fields/dynamics, произвольные внешние ссылки и деформация
чужих prefab.

## Контрольные точки и GitHub

После проверенного шага: diff, затронутые тесты, независимое correctness review
нетривиальных изменений, EN/RU статус, checkpoint commit и обычный push в
[MaikiOS/BuildWorks](https://github.com/MaikiOS/BuildWorks). Разрешено Ostrix
2026-09-30. Сохранить чужие изменения. Только исходники/безопасные документы:
без force-push, saves, игровых DLL, личных путей/логов и автоматических релизов.
При ошибке синхронизации сохранить commit и сообщить точную ошибку.

Пауза — дизайн/иконки, подготовленная игровая серия, новое обсуждение кривых.
Продолжать от текущей точки, не архивного STOP. Новый блокер доступа/безопасности
сообщать честно. Установка не разрешает запуск игры и изменение saves.
