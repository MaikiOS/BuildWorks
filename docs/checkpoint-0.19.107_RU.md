# .107 — фактическая оплата и безопасная отмена текущей стройки

QA .107 установлена штатным скриптом; хеш совпал,48 файлов saves/receipts и библиотека неизменны. Игра не запускалась.

Это исправление существующего последовательного строительства. Постоянные задания
с колышком, административное восстановление и устойчивость при аварии ещё не реализованы.

Раньше отмена вызывала `Piece.DropResources`: возврат рассчитывался из рецепта,
а не из фактического расхода. Бесплатная стройка могла выдать материалы; свойства
затраченных предметов не учитывались. Теперь отдельная запись для каждой созданной
детали хранит точные списанные стопки и копии их свойств. Держатели предметов
возвращают содержимое своим штатным путём отдельно от строительных материалов.

Учёт завершается после `Player.UpdatePlacement`, включая частичное списание при
исключении. Последняя деталь больше не очищает сессию до этого момента. Прямой
`TryPlacePiece` вне учтённого `UpdatePlacement` не разрешает стройку чертежа.

Возврат требует трёх подтверждений: выполнен `WearNTear.Destroy` с подавлением
штатного выпадения ресурсов; исходный ZDOID действительно добавлен владельцем
в native очередь; именно эта сетевая запись удалена в том же живом сеансе.
Штатная очередь отправляется сразу после batch отмены, чтобы выход в меню не
потерял возврат из-за ожидания следующего кадра. Исчезновение локального объекта,
чужое владение и очищенная при shutdown таблица не являются подтверждением.

Неопределённый результат native удаления, отправки или выпадения предмета блокирует
повторную выдачу: повтор после возможного уже состоявшегося выпадения создавал бы
дубликаты. Это предотвращает автоматическое дублирование, но не обещает восстановление
ресурсов после аварии/разрыва сети: для него нужен постоянный серверный журнал.
Детали без `ZNetView` отклоняются до стройки; в редакторе их записи сохраняются.
