# BuildWorks — сохраняемые рецепты паттернов и кривых

Статус: согласованное направление после Astra-аудита 2026-09-09. Это спецификация будущих этапов, а не заявление о готовой реализации.

## Цель

Редактировать существующую деталь или группу как источник, видеть живой результат цепочки операций, сохранять параметры и в любой момент возвращаться к ним. В мире результат остаётся обычным набором native-деталей Valheim.

## Модель

- Группы остаются структурой дерева и не становятся transform-узлами.
- У группы может быть один локальный `PatternRecipe` со стабильным ID, собственным исходным snapshot поддерева и упорядоченными операциями.
- `Parts/Groups` хранят последний проверенный материализованный результат. Каждый пересчёт начинается только с canonical source snapshot, поэтому повторный scrub/save/reopen не накапливает drift.
- Операция имеет stable ID, тип, enabled, цель (`каждая деталь` или `каждая непосредственная дочерняя сборка целиком`), пространство осей, pivot и типизированные параметры.
- Transform-операция не меняет ID исходных частей. Генератор даёт детерминированные ID из `(recipeId, operationId, sourceId, logical coordinates)`, а не новый GUID на каждом preview.
- Мировая опора сохраняет свою identity и следует итоговому pose той же детали. Она не переключается автоматически на копию.
- `Превратить в обычные детали` явно удаляет procedural-связь одной Undo-операцией. Ручное изменение отдельной созданной копии до Bake не допускается молча.

Порядок вычисления:

`source snapshot → операции по порядку → validation → preview → один atomic commit → обычные Parts/Groups → мировая опора/snap → native placement`

Preview и commit используют один `EvaluationResult`. Если документ изменился после preview, результат пересчитывается до подтверждения.

## Операции по этапам

1. **Rigid Transform stack** для существующей группы: независимые position/rotation/uniform scale, локальные оси элементов, общий pivot, собственные pivot элементов, масштабирование только расположения, радиальное смещение, enable/reorder/remove/Bake.
2. **Array generator**: ряд/сетка/радиальный вариант; источником может быть деталь или поддерево группы. Переиспользуется текущая математика Array, но добавляется стабильная identity и remap опор копии.
3. **Line guide**: точки A/B, шаг либо количество, reverse, базовая ориентация.
4. **Polyline**, затем отдельно **Arc** и **Bezier**. Переиспользуется `GuidePathSampling`, но устойчивые tangent/normal frames реализуются и проверяются отдельно.
5. Существующий Contour переводится на тот же evaluator с фиксированным reference support ID.
6. После реального спроса: Step, Align/Target, seeded Random и простое линейное/радиальное влияние.

Не входят в первые этапы: деформация mesh обычных prefab, shear/неравномерный масштаб геометрии, node graph, expression language, arbitrary external references, full Fields, dynamics и MoGraph-анимация.

## Сохранение

Первый recipe-релиз повышает Store до v10 и добавляет необязательное `recipes`.

- v9 без recipes читается без эвристического восстановления и без изменения transforms/IDs.
- Неизвестный `recipeVersion` или `kind` блокирует перезапись файла с сохранением оригинала.
- `Document.State`, Copy/Undo/Redo, duplicate/insert и Store round-trip включают source, операции, порядок и materialized result.
- Пересекающиеся owners и recipe внутри recipe отклоняются до отдельной спецификации вложенных зависимостей.
- Лимиты проверяются по конечному результату вместе с остальным документом: editor 128 частей/64 группы, world expansion 512.

## UX-контракт

- Обычная гизма остаётся обычной трансформацией; у активной операции — только её понятные ручки.
- В Outliner у группы появляется раскрываемый раздел `ОПЕРАЦИИ`; активна одна операция, порядок виден и изменяем.
- Добавление: выбрать группу → `+ ОПЕРАЦИЯ` → выбрать тип → живой preview → `ПРИМЕНИТЬ` или `ОТМЕНА`.
- Нижняя строка всегда показывает только доступные сейчас клавиши и следующий шаг.
- Для кривой путь: `начало → узлы → источник → шаг/ориентация → preview → Apply/Cancel`. Не обещать клавиши или tangent-handles до их actual pointer реализации.

## Ворота приёмки

- 100 одинаковых evaluation дают byte-equivalent transforms и те же stable IDs.
- 0%/disabled возвращают source; Cancel/error не мутируют документ.
- Preview равен commit и Bake; один Apply/Bake — один Undo.
- Position/layout меняются без изменения размера prefab.
- Вложенная сборка в режиме `целиком` сохраняет внутренние расстояния.
- Reorder, disable, Undo/Redo и save/reopen воспроизводят один результат без drift.
- Изменение размеров Array не переименовывает сохраняющиеся logical cells.
- Legacy v9 round-trip не меняет frame, опоры и координаты.
- Curve tests покрывают endpoints, reverse, равномерность шага, вертикальный участок, нулевую касательную, острый поворот и отсутствие случайного roll flip.
- Actual Unity pointer tests покрывают scrub, nodes, Esc, Apply/Bake; Valheim placement/reload и multiplayer остаются отдельными ручными воротами.
