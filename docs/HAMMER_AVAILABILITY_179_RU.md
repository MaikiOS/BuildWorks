# Доступность деталей молотка — .179

Исправлена воспроизведённая ошибка: BuildWorks мог отказать детали, которая есть в полном доступном наборе Valheim, если списки категорий или их кеш ещё пусты/устарели. Теперь разрешение берётся из native `PieceTable.m_availablePieces`, а не из списков, используемых для поиска/страниц интерфейса. Устаревший кеш также не может разрешить деталь, исключённую игрой из этого набора. Изменение полного набора обновляет регистрацию карточек.

Точное имя prefab и принадлежность текущему `Player.m_buildPieces.m_pieces` по-прежнему обязательны. `ZNetScene.GetPrefab` используется только для объяснения отказа; он не разрешает строительство. Открытие рецептов, enabled/сезонные настройки, ресурсы, станции, обычное размещение и сетевые проверки не обходятся. `EnsureVisible` сначала проверяет native доступность, затем может показать уже разрешённую деталь в своей категории при запаздывании кеша. Встроенный native интерфейс сохраняет собственный порядок.

Для **QA175 Forest Hut** подтверждены28 записей и четыре `wood_wall_roof`. В реальной сохранённой копии у них есть имя «Деревянная стена 26°», basis1 и bounding box. `metadata.hostId` совпадает с MVID текущей assembly_valheim: prefab был доступен при сохранении. **Причина отказа именно этой хижины ещё не доказана:** нет свежего снимка её текущего инструмента/known recipe/native set. Нельзя утверждать, что обычная пагинация была причиной: прежний AllLists уже учитывал все страницы. Исправлен отдельный проверенный случай рассогласования/устаревания UI-кеша.

Отказы теперь различают: нет активного инструмента; prefab не загружен; объект не поддержан как строительная Piece; загруженная деталь отсутствует в текущем инструменте; деталь есть в нём, но native игра её не разрешает. «Проверить чертёж» показывает и пишет в лог факты: physical, имя текущей table, inTable, enabled, IsRecipeKnown, nativeAvailable, реальные ресурсы и станцию. Они помогают установить причину без подстановки ID/выдуманной цены.

Доказательства: до исправления actual native PieceTable regression отказал на `Native complete available set was hidden by empty/stale category caches`; после исправления тот же тест прошёл. Дополнительно проверены показ разрешённой детали до обновления кеша, запрет устаревшего разрешения, изменение registry signature и отсутствие UI-изменения после отказа. Это настоящие типы из текущей assembly_valheim с инертными данными в изолированной Unity, не игровая стройка. Native IL подтвердил полный HashSet, known recipe по m_name и отдельность IsKnown/CanBuild; полный набор не заменяется самодельным вычислением правил.
