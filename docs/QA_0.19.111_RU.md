# .111 — явная копия без экипировки и позы стойки брони

Сценарий подготовлен для последующей ручной проверки, в игре ещё не выполнен.
Только изолированный QA мир в профиле TerrainRamp-1.0-Test, запуск через Modded.
Для этой проверки не нужны материалы, открытые рецепты или строительство стенда.

Файл: `10-armor-state.blueprint`, название `QA111 Armor State`, две детали.
Папка для «Изменить путь» → «Открыть»:

```text
C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\Default\BuildWorks\tests\fixtures\armor-state
```

Исходное состояние: установленная QA .111, игра в изолированном QA мире;
каталог редактора или молотка открыт. Исходный файл не редактировать.

1. Нажми «Импорт файла», открой указанную папку и выбери файл.
   Снова нажми «Импорт файла». До подтверждения новая копия не создаётся.
2. В проверке должны быть одна неподдерживаемая запись и строка источника
   `10-armor-state.blueprint · ArmorStand`, количество1. По умолчанию выбрано
   «Стойки брони: СОХРАНИТЬ НЕПОДДЕРЖИВАЕМОЕ СОСТОЯНИЕ».
3. Выбери «Стойки брони: КОПИЯ БЕЗ ЭКИПИРОВКИ И ПОЗЫ».
   Ожидается предупреждение: экипировка и поза одной стойки в копию не переносятся,
   исходник сохраняется, других неизвестных записей0. Прокрутка списка должна работать,
   если список не помещается. Нажми «Назад к параметрам файла», затем «Импорт файла».
   Ожидается исходный выбор сохранения состояния, а не прежнее исключение.
4. Снова выбери копию без экипировки/позы, затем «Подтвердить импорт».
   Результат должен содержать путь отдельного ZIP. Закрой окно, найди новую карточку
   `QA111 Armor State` и открой «РЕДАКТИРОВАТЬ». Должны сохраниться обе записи,
   стойка находится в2м по X от стены. Одежда и исходная поза не обещаются.
5. На карточке копии нажми «Экспорт файла», выбери BuildWorks JSON, отдельное имя
   и папку. Подтверди экспорт. Повторный импорт этой копии не должен возвращать
   исключённую экипировку из сохранённого исходника.

Ошибка: потеря стены/стойки или координат, автоматическое исключение без выбора,
изменение исходного файла, возврат экипировки после повторного импорта, нечитаемое
предупреждение, перекрывающиеся кнопки или сохранённый после «Назад» выбор исключения.
Если ArmorStand недоступен, должна сохраниться запись с неопределённостью; это не
основание выдумывать масштаб или разрешать строительство. Отдельные ошибки renderer
или размещения необходимо записать; этот сценарий их заранее не объявляет исправленными.

Это проверка выбора и сохранности данных. Стройка пустой стойки, расход ресурсов,
сохранение мира, повторная загрузка и multiplayer остаются отдельными проверками.
Полное восстановление экипировки ArmorStand ещё не реализовано.
