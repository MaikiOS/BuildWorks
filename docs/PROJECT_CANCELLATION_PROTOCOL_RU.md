# Оплаченная отмена: границы и план реализации

Подтверждённое поведение: отмена возвращает фактически потраченные предметы с их свойствами выпадением рядом с табличкой. Неоплаченный проект просто исчезает. Старое состояние предметов не восстанавливается, повторной выдачи нет. Рельеф не меняется. Общая будущая табличка/хранилище — отдельная [граница EarthWorks](EARTHWORKS_BOUNDARY_RU.md).

Ниже технический проект, а не готовая функция или утверждённый новый интерфейс. Начальное ограничение: private Local host, тот же оплачивающий игрок, проверенные ванильные конструктивные части. Сеть, содержимое и произвольные `IRemoved` требуют отдельного доказательства.

## Порядок и сохраняемые состояния

1. Заморозить продолжение; дождаться и сверить pending исполнения. Зафиксировать cancel ID, проект/revision, часть/receipt, мир, плательщика и точные PaidRows. Неизвестное состояние останавливает отмену.
2. Проверить живую уникальную собственную часть; сохранить намерение удаления, подавить обычные native drops и удалить. Сохранить мир, проверить отсутствие всех целевых меток одним полным mapped scan. .237 реализует только этот последний read-only примитив.
3. Для каждого возврата сохранить IssueIntent, затем создать ItemDrop у таблички с отдельной ZDO-меткой cancel/row/receipt и закрытым подбором. Метка должна ставиться в раннем spawn-пути, включая исключение после Instantiate; голое окно между spawn и tag недопустимо. Доказать точные native данные предмета и сохранённый единственный drop, затем записать Issued. Это уже выдача, ещё не подбор.
4. После сохранённой выдачи всех строк завершить отмену, убрать табличку/туман; журнал выдачи оставить. Подбор маркированного drop сохраняет CollectIntent и точный inventory-before; помещает исходный предмет в проверенную пустую ячейку без штатного merge, подтверждает сохранённый профиль, затем удаляет drop и подтверждает сохранённое отсутствие. Лишь после этого Collected.

## Сбой и повтор

| Наблюдение после восстановления | Решение |
| --- | --- |
| Часть отсутствовала до контролируемого удаления | Не считать возврат безопасным: обычные drops могли уже выпасть |
| Намерение удаления, но исход неизвестен | Сверка receipt/живого и сохранённого состояния; неопределённость блокирует выдачу |
| IssueIntent, метка drop не найдена | **Не создавать автоматически заново:** отсутствие не доказывает, что предмет никогда не выдавался/не подобран |
| Найден один точный закрытый drop и сохранённая выдача | Продолжить по журналу, без повторного spawn |
| Дубликат, неизвестное слияние, неполные данные | Остановить конкретную строку, сохранить доказательства |
| CollectIntent и точный сохранённый inventory-before/after | Продолжить только однозначную ветвь; частичный результат не угадывать |
| Issued drop исчез без доказательства Collect | Остановить строку, не выдавать повторно |

Native `Inventory.FindFreeStackItem` не учитывает все customData/variant: item customData не подходит как единственная долговечная идентичность возврата. Использовать ZDO-метку и проверенный pickup-путь; до реализации запрета pickup/auto-stack/despawn/cleanup функция не включается. Поведение при отключении мода остаётся отдельным риском.

## Следующие проверяемые срезы

- Сохраняемый cancellation journal и переходы с fault injection.
- Контролируемое удаление/подавление drops и game save/readback.
- Ранний tag+seal spawn, точное чтение ItemDrop.SaveToZDO, Issued/Collected.
- Проверка сбоев между каждым шагом; native прогон отмены/подбора/reload, затем сервер.

До этого оплаченная кнопка отмены остаётся закрытой. Положительное чтение файла, RAM refund-флаг или absence proof не заменяют весь протокол.
