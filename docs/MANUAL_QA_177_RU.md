# Короткая ручная очередь .177

Установлена0.19.177.0, SHA и190 config-файлов проверены: [протокол](MANUAL_FIXES_177_RU.md). Проверять, когда удобно. Игра запускается через Thunderstore → TerrainRamp-1.0-Test → Modded, прежний QA-мир/персонаж. Материалы не нужны. Принятые авто17/18, масштаб/крайние значения, SaveAs, обычную камеру и отказ полностью missing заново не проверять.

1. **Подсветка плоскости.** Файл `16-supported-snap.blueprint` в `BuildWorks/artifacts/manual-qa-169`; открыть свою редакторскую копию, выбрать деталь. G → X → Z: золотая плоскостная ручка должна лежать между X и Z, не между Y и Z. Esc. Аналогично XY и YZ, в мировых и локальных осях. Ошибка: подсвеченная плоскость не соответствует паре. Не сохранять изменения оригинала ради этого теста.
2. **Продолжение мышью.** В той же копии S, затем G → X → Z и R → Y; для каждой новой операции провести через все четыре края области модели и обратно. Ожидается непрерывное изменение без повторного S/G/R. Если перенос не подтверждён backend, сообщение должно сохранить достигнутый предпросмотр; Enter подтверждает его, Esc отменяет. Это безопасный отказ переноса, а не успешная непрерывность. При клике по кнопкам сетки/проекции преобразование не подтверждается само. Ctrl даёт доступ к панелям. Alt+Tab/Esc/выход освобождают ввод. Ошибка: внезапный откат/выход из операции без Esc, скачок или случайное подтверждение модельного изменения. Для сохранённого пробного результата использовать отдельное имя **QA177 Cursor**, а затем Undo; старые копии не переписывать.
3. **Повреждённый файл.** `32-invalid-json.buildworks.json`, тот же каталог файлов → «Импорт файла». Ожидается понятная ошибка самого файла без `{0}` или выдуманного номера строки; можно закрыть окно и выбрать другой файл. Карточка не создаётся. Полностью missing файл30 уже проверен, повтор не нужен.

**Forest Hut не объявлен исправленным для строительства.** В последнем QA-логе четыре `wood_wall_roof` недоступны в текущем молотке. В .177 вместо общего «чертёж недоступен» должен показываться конкретный отказ resolver. Это исправление сообщения, не разрешение недоступного рецепта. Не надо снова импортировать/строить заведомо заблокированный дом: следующая задача разработчика — разделить загруженный prefab, наличие в текущем молотке и открытый рецепт, затем подготовить проверяемый путь без бесплатного обхода правил.

**Разъяснение старых тестов.** Файл26 намеренно растягивает табличку(1.5,.5,2.25), поэтому форма/текст могут быть деформированы; отсутствие текста в editor/ghost остаётся проблемой. Файл27 проверяет только XYZ точек и предупреждение о неразобранных дополнительных полях. Файл29 — экспорт отдельной пустой копии контейнера старого формата106, исходник должен сохранить предмет; это не тест его строительства. Старый пункт11 означает сравнить конкретно созданный результат после выхода/входа. Пока новой успешной хижины/меча не было, не засчитываем полный путь и не просим повторный reload без такого объекта.
