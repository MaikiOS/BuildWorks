## Исправление чтения ответа

После завершённого запроса05 клиент получил Windows sharing violation при
ReadAllText(response.json). Команда не повторялась; готовый ответ восстановлен.
При запросе06 также наблюдалось временное отсутствие response.json; итоговый
ответ и кадр прочитаны позднее, без повторной отправки.

Читатель теперь допускает замену открытого файла, читает максимум32769байт,
закрывает поток до разбора JSON и делает максимум5 попыток только чтения
при Windows2/32/33 с паузой10ms. Ограничение32768, проверка reparse point,
строгие UTF8/JSON, nonce/PID и одноразовая отправка сохранены.
Запросы07/08/09 завершились с исправленным клиентом. Установка не менялась.

`tests/BuildWorks.QaControlTests/Read-ControlJsonChecks.ps1` извлекает настоящий
helper: граница размера, повреждённые UTF8/JSON, временная/постоянная блокировка,
временное/постоянное отсутствие файла и100 одновременных атомарных публикаций.
Первоначальные успешные прогоны чередовались с отказом writer File.Replace
«Не удается удалить заменяемый файл» даже вне песочницы, при интервалах1/50ms.
Поэтому один читатель не признан полным исправлением. HRESULT0x80070497
(Windows1175) воспроизведён отдельно при конкурентном чтении; конкретная причина
в Windows/фильтрах/дескрипторах не установлена. Ошибку нельзя считать только
ограничением песочницы. Старое ReadAllText при этом отдельно вызывало sharing violation.

## Исправление .146, установлено после завершения игры

Добавлен QA-only BuildWorksQaFilePublisher: максимум5 попыток File.Replace
над тем же закрытым temp, только при IOException1175,10ms между попытками,
повторная проверка путей и запись восстановленного сбоя. [Контракт Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)
гарантирует сохранение исходных имён обоих файлов при1175. Ошибки32/1176/1177
и ошибки проверки путей не повторяются. Игровые команды не повторяются.
Суммарное дополнительное ожидание главного потока — до40ms, только в QA.

Тесты используют настоящий C# helper и PowerShell-читатель. Windows1175 и граница
повторов проверяются через fault injection только в тестовом EXE; механизм подмены
отсутствует в игровой QA DLL. Реальный конкурентный File.Replace проверяется
при интервалах1/50ms; протокол — `artifacts/qa-channel-smoke-2026-10-11/final-checks.log`.
Normal/QA0/0, compiled control/native input contract, isolation и localization973
прошли. Независимые correctness/ponytail обзоры: блокирующих замечаний нет.
После завершения Valheim .146 установлена через Deploy-TestBuild; обе DLL сверены по SHA. Все154 текущих config/import/save файла неизменны, Default чист. После нового Modded-запуска повторить только канал/ответы, не всю принятую серию.
