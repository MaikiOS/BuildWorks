# Замер импорта .177 — отдельная копия внешней библиотеки

13 октября2026. CPU StoreTests собраны из текущих исходников. QA imports прочитаны и скопированы в private artifacts; blueprints.json, token, квитанции, thumbnails, exports и saves не изменялись. Отдельная проба catalog-phases: чтение библиотеки1,848/1,850с; синхронная подготовка/планирование0,058/0,048с; оставшийся worker0,845/0,791с; публикация<0,001с. Независимые пробы нельзя складывать как последовательные стадии. OS/JIT caches не сбрасывались. Одновременно работала offline Unity UI-проверка, поэтому это диагностический замер под нагрузкой, не изолированный эталон скорости.

Вывод: маленький импорт участвует в проверке общей большой библиотеки и её следующем обновлении; обещать моментальность на основании четырёх деталей неверно. Нельзя утверждать, что все записи каждый раз полностью конвертируются: внутри операции есть validationReads и кеш точных исходных строк. Native prefab/metadata, интерфейс и миниатюры в этих пробах не выполняются и могут добавлять задержку.

Следующее исправление: показывать реальные этапы и после успешной публикации выбирать результат по ID+importSource; затем уменьшать повторное чтение/проверку неизменённых архивов с сохранением проверки целостности/изменения источников. Прогресс не должен показывать выдуманный процент, а закрытие импорта не должно начинать строительство. Групповой импорт — отдельный сценарий, не слепой цикл одиночных подтверждений.
