# .138 — повторная работа при файловой конвертации

Код b89cac712e15e2853fb13111d5502b42c1c8f848. Установлено только в
TerrainRamp-1.0-Test; SHA пары сверены, Default чист,137 существующих файлов
config/import/save сохранили хеши, размеры и точные UTC-даты. Игру не запускали.

В PrepareForHost и ReviewImportFile таблица допустимых обычных ZDO-полей теперь
создаётся лениво один раз на документ, а не на каждую деталь. Она не разделяется
между документами/хостами/hash callback. Unknown/type/source-binding проверки
сохранены. Number напрямую возвращает float только для точных строк0/1/−1 после
legacy blank/comma; остальные строки идут через прежний invariant float.Parse
и отказ NaN/Infinity. Формат, исходники, цены, права и размещение не менялись.

До изменения регрессия дала Ordinary ZDO field table rebuilt per part:64.
После: один раз для64 строк в подготовке и review, независимые salted hash,
unknown siblings и неизменный источник. Числовые тесты сравнивают точные float bits,
включая signed zero/пробелы/экспоненты/legacy comma/blank; NaN/overflow отклоняются.
Полный Store прошёл, normal/QA0/0, Host25185596, локализация948, compiled isolation,
launch preflight и оба независимых обзора PASSED/Ship. verify отсутствует.
Geometry и Unity не перезапускались: математика/рендер/UI/input не менялись;
предыдущие выделенные прогоны .136/.137 не являются игровым доказательством .138.
