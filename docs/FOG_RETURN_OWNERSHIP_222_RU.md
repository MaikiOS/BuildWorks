## Что установлено

В утверждённой лаборатории стена стоит поперёк X, вдоль Z. Игровая длинная стена из4 соседних native woodwall стоит поперёк Z, вдоль X. `AccumulatedSmoke.compute/SourceBin` в обоих случаях использует только `RestUV(p).yz`: исходная X теряется. Раздельные владельцы деталей не исправляют смешение мест внутри одной детали. Камера на эту индексацию не влияет.

GPU-воспроизведение использует **тот же compiled candidate bundle**, что native .221: SHA `A24A7CED68795563AAE47A40113BB55C6944E4DA2D0FDC7BF32A1B023F5CF99E`. Один искусственный displaced sample создаёт ровно1024 единицы away-mass в одном bin524. Эмиссия выключена, тело далеко, начальное повреждение0,5. Настоящие ядра AccumulateLedger и AdvanceVelocity показывают:

| Проверяемое место | Прежний solver | Изолированный Spatial3D-кандидат |
|---|---:|---:|
| Источник A: его туман ещё не вернулся | 0,5 | 0,5 |
| B: другое место, +1,8м по X, те же Y/Z | **0,5 — ошибочно удерживается** | **0,458251953 — восстанавливается** |
| Контроль: другое место по Z | 0,458251953 | 0,458251953 |

Это доказывает ошибочное удержание **ранее повреждённого** другого места, а не появление новой дыры без контакта. Синтетический опыт отделяет причину от камеры, траектории, таймера и общего отсутствия восстановления. Он не устанавливает, что это единственная причина всех сообщённых визуальных сбоев.

Первый GPU-запуск остановился с `Ownership probe readback incomplete`: прочитан лишь один слой 3D-текстуры. Исправлен сбор всех слоёв с проверкой полного объёма; исходный отказ сохранён. После этого legacy reproduction и отдельный3D-кандидат завершились exit0. Независимый обзор подтвердил причинность и границы; `verify` skill отсутствует.

## Что проверено у кандидата и что ещё нет

`scripts/Prepare-FogOwnershipCandidate.py` сверяет hash текущего shader с manifest compiled bundle и создаёт **только generated test fixture**. Меняются индексация bins на16×32×32 и3D-окрестность; остальные ядра и порог768 не меняются. Воспроизведённый alias устранён, away-mass сохраняется1024 в bin8389. Runtime bundle и исходный compute не перезаписываются. Перед RunCandidate нужен этот скрипт; generated shader и локальные игровые assets не входят в source-only GitHub.

Этот опыт **не проверяет** полный цикл транспорта, смешение исходных позиций, распределение массы между слоями, частые повторные контакты, yaw0/90, наклон/масштаб/неплоскую модель, образ v11, native rendering, FPS, budget enforcement или проект/табличку. Значение `.5→.45825` подтверждает конкретное разнесение источников, а не художественную приёмку.

## Граница следующей реализации

Нужен неизменный layout на весь pool/generation: LegacyYZ для точного эталона v11 и Spatial3D для игрового кандидата. Не переключать живые owners, не переносить старые peak/away между схемами, не выбирать плоскость по эвристике похожести на стену. Runtime wiring включает solver/staged validation, owner и shared-stage buffers, arena copy/commit dispatch, полный расчёт бюджета. Source/map/payload/velocity-формат этим менять не требуется; Ledger[2] остаётся одним флаговым uint.

При прежних28 owners/7 resident/8192 blocks рост **всех29 пар** owner+stage ledger:
`29 × (16384−1024) × 8 = 3 563 520 B`.
Итого `94 478 116→98 041 636 B` при лимите98 304 000, запас262 364 B. Это расчёт, **не измеренная production-аллокация и не доказанный бюджет тяжёлого дома**. Более крупный storage reserve дома пока не обеспечен; four-wall32768 относится к другому fixture. Защиту бюджета не отключать.

3D bins всё ещё приближение: дым хранит усреднённое исходное место; размер ячейки `.30×.140625×.10625м` не вращательно-инвариантен. Порог768 и расширенная окрестность могут изменить длительность возврата при разделении массы. Следующие обязательные проверки: immutable layout/границы/отказ бюджета → legacy exact → разнесённые X источники → одинаковые yaw0/90 и неплоская деталь → полный проход/удержание/выход/повторный вход и поля/изображения → согласованная native close-camera запись длинной стены → дом. Проект и колышек следуют после доказанного v11, оставаясь основным результатом цели.
