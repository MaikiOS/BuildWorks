# .145 — предметы креплений отдельно от строительной цены

Код `fc07cf3`, независимые обзоры PASSED/Ship. Установлена QA0.19.145.0 только
в `TerrainRamp-1.0-Test`; обе DLL сверены,139 защищённых файлов сохранили байты,
размер и время записи, Default чист. SHA QA DLL:
`DA2B5E51A12ABE7F132D55108C7B00FE293DA9EF93D76A3119CCA6147AFC7BBA`.
См. `artifacts/checkpoint-0.19.145/verification.json` и `installation.json`.

До изменения каждый выбранный предмет проверялся отдельно. Если три крепления
использовали один стек, оставшихся двух предметов было достаточно для каждой
отдельной проверки, хотя для всего остатка проекта их уже не хватало. Кроме того,
native стройка могла потратить выбранный предмет как материал следующей детали.

## Реализовано

- Перед `TryPlacePiece` проверяется совокупный остаток удерживаемых предметов.
  Проверка охватывает первый ручной запуск и автоматическое продолжение.
- Цена только следующей детали прогнозируется по текущему native порядку:
  требования последовательно, затем стеки по порядку списка инвентаря;
  сопоставление по shared-name, все качества, фильтр world-level, флаг станции
  upgrader и соответствующий `FreeBuildKey`. Разные prefab с одним shared-name
  конкурируют за оплату. Общий запас сам по себе не доказывает безопасность.
- Перед отложенной передачей предмета повторно проверяются все удерживаемые
  ссылки, количества и сохранённые свойства. Другой предмет не подставляется.
- Успешная или пропущенная деталь освобождает свою запись резерва; закрытие
  очищает резерв. Список содержит только предметы креплений; обычная постройка
  без содержимого проходит быстрый пустой путь.
- При конфликте размещение приостанавливается до native создания/оплаты.
  Сообщение предлагает добавить ресурсы в тот же стек либо отменить, изменить
  порядок инвентаря и подготовить чертёж заново. Поздний свободный стек не всегда
  помогает: native может первым списать выбранный стек.

Проверка ничего не списывает, не сортирует инвентарь, не меняет архив и не
требует сразу всю стоимость постройки. Реальное списание и передача предмета
остаются в существующем native пути после завершения оплаты.

## Доказательства и границы

`artifacts/checkpoint-0.19.145`: normal/QA0 ошибок и предупреждений,
HostContract Steam25185596, localization973, Store, изоляция, EditorBridge,
QA control contract/protocol28, установщик на копии16 случаев и4 запрещённых
профиля, preflight. Unity6000.0.61f1 Workbench:492 снимка и новая регрессия
`ReservationChecks`. Проверяется настоящий код адаптера на инертных типах host;
это не запуск Valheim. Четыре метода оплаты закреплены IL-хешами, аргументы
native вызова `ConsumeResources(resources,0,-1,1)` проверяются отдельно.

Регрессии: достаточный общий запас при опасном первом стеке; безопасный другой
порядок; повторяющиеся требования; освобождение выполненного резерва; нехватка
совокупного остатка после оплаты; изменение свойств будущего предмета;
shared-name alias; world-level; станция upgrader; независимые бесплатные ключи;
бесплатная стройка не отменяет необходимость предметов; сохранность источника,
инвентаря и привязанных ссылок.

Содержимое непустого сундука по-прежнему блокируется, если его явно не исключить
из временного рецепта. Общего резерва N предметов сундуков, переноса, учёта
фактических передач/отката, постоянных операций и server ack ещё нет.
Неизвестные сторонние изменения списания не считаются поддержанными этим
прогнозом; перед передачей выполняется проверка фактического остатка.
Native стройка, отмена, reload, сеть и первый ввод QA-канала ещё не проверены.

Для игровой проверки канала: [точный запуск](QA_CONTROL_RU.md).
Для штатных креплений/пустого сундука используются уже подготовленные
[файлы24/25 и протокол](QA_0.19.144_RU.md); ранее принятые случаи не повторяются
без причины. Внешний мод с иной ценой/списанием требует отдельной проверки.
