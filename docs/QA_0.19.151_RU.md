**Сейчас не выполнять: установлена .146.** После освобождения Ostrix Codex сначала
установит одну проверенную QA не ниже .153 через Deploy-TestBuild, сверит DLL и
назовёт версию. Thunderstore → TerrainRamp-1.0-Test → **Modded**, существующие
QA-персонаж/мир BW_QA_43d3719a. Основной мир не использовать. Ресурсы не нужны:
серия проверяет окно импорта, существующий тест строительства не повторяет.

Исходный файл: `26-planbuild-decimal-comma.blueprint`, папка
`C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\Default\BuildWorks\tests\fixtures\planbuild`.
Карточка результата: **QA147 PlanBuild Comma**. При повторном импорте отдельная
копия ожидаема; это не самопроизвольное дублирование каталога.

1. Каталог редактора → «Импорт файла» → указанная папка → файл26 → «Импорт файла».
   Ожидание: обзор появляется после ожидания; «Подтвердить импорт» недоступно до
   готовности. Нажать «Назад к параметрам файла», снова выбрать файл. Ошибка: зависшее окно, старые
   сведения/неактивные файлы, сообщение устаревшего контекста без смены мира.
2. Дождаться обзора → «Подтвердить импорт». Ожидание: сообщение об успешном импорте
   с читаемым путём; после завершения окно не остаётся в «Загрузка». Закрыть,
   найти QA147 PlanBuild Comma → «РЕДАКТИРОВАТЬ». Одна табличка и «Привет, мир».
   Подробная форма/сохранение входят в уже открытую серию26 .147, объединить с ней.
   Ошибка: импорт записан, но результат никогда не появляется; окно блокируется
   после завершения, источник изменён, неверная карточка/лишние детали.
3. Для ожидания/«Назад» на большой библиотеке Codex заранее подготовит отдельную
   временную QA-копию `artifacts/external-blueprints/BiomeBlueprints-1.0.3/package.zip`
   и проверит бюджет/точный результат под текущими prefab. **Пока не подготовлено**:
   пользователю архив целиком сейчас не импортировать. Ожидание этой будущей пробы:
   доступные «Назад»/закрытие во время подготовки, отсутствие позднего открытия
   старого обзора и записи при отказе, новый импорт после возврата работает.

Смена мира во время обзора, ошибка чтения/записи, молоток и разные разрешения —
следующие подготовленные QA случаи; CPU-проверки не заменяют их. Сообщить номер
шага, версию, кадр и свежую ошибку лога. Полный путь редактор → призрак → стройка →
reload/сеть остаётся отдельной основной проверкой.

Для .152 после отказа worker причина должна оставаться видна несколько кадров,
а повторное подтверждение — недоступно до «Назад к параметрам файла» и нового
обзора. Безопасный файл/условия такого отказа Codex подготовит отдельно; не ломать
установленные prefab и не менять исходную библиотеку ради проверки.
