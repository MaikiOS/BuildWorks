# Подготовка замера локальной модели на кадрах Valheim

Обновление: реальные измерения трёх моделей выполнены; чистое зрение не прошло.
Qwen3.5 с записанным native UI-состоянием выбирает команды6/6; локальный pilot
подготовлен, QA .164 установлена, runtime/FPS ещё не проверены.
[Результаты и запуск](LOCAL_QA_AGENT_2026-10-12_RU.md). Ниже исходный протокол.

`scripts/Measure-QAVision.py` использует только стандартную библиотеку Python.
Он не вызывает игровой QA-канал, не посылает ввод, не читает сохранения и не
меняет плагины. Без `--run-inference` нет даже обращения к Ollama.
Разработан для запуска из исходного BuildWorks; сохранённые PNG остаются
локальными артефактами и не включаются в source-only Git.

## Входы и проверка результата

Три кадра из реальной серии .162 просмотрены агентом; имена/SHA и ожидаемые
признаки закреплены в `specs/qa/vision-162.json`:

| Файл | Наблюдаемое состояние |
| --- | --- |
| native19.png | Выбран молоток и TEST24; нижний HUD чертежа, окно сундука закрыто |
| native22.png | Молоток не выбран; наведение на закрытый сундук, нет сетки инвентаря |
| native23.png | Открыт сундук; его сетка пуста, молоток/чертёж не выбраны |

Модель получает изображение и один общий вопрос, без эталонных ответов и
скрытого игрового состояния. Ответ — четыре наблюдаемых признака, без действий.
Проверяются точные ключи, JSON bool, допустимый вид; лишние команды, дубликаты
ключей, обрезанные/незавершённые ответы отвергаются. Валидный неверный ответ
сохраняется как ошибка распознавания, а не успешный тест.

## Команды

Из `Default/BuildWorks`, через PowerShell7:

```powershell
python.exe scripts/Measure-QAVision.py --self-test
python.exe scripts/Measure-QAVision.py
```

Это безопасная CPU-проверка. Шесть test cases покрывают строгий разбор, отсутствие
API по умолчанию, отказ изменённого кадра, дубли JSON, запрет перенаправления
локального HTTP и весь цикл на подставных ответах:6 успешных запросов либо
остановку после первого обрезанного ответа с сохранением ошибки. Подставные
ответы не являются доказательством распознавания или скорости модели.

Только при отдельном разрешённом запуске вычислений:

```powershell
python.exe scripts/Measure-QAVision.py --run-inference
```

По умолчанию `qwen3-vl:4b-instruct`, уже установленная в Ollama. Ничего не
скачивается. Фиксированный API `127.0.0.1:11434`, без HTTP proxy/redirect.
Сначала сохраняются сведения о модели и загруженных моделях; затем каждый из
трёх кадров обрабатывается дважды. Контекст4096, максимум128 выходных токенов,
temperature0. Модель может оставаться в памяти60с после последнего запроса;
скрипт не выгружает чужие модели. При таймауте сервер ещё может считать:
автоматического повторения нет. Не запускать параллельно рабочему GPU-заданию.

Отчёт: `artifacts/qa-vision/<время>-<ID>/report.json`, уникальный каталог.
Он содержит полный ответ, ошибки по каждому признаку и фактическое полное время
от чтения изображения до ответа. Ответ Ollama отдельно содержит load/prompt/eval
durations. Первый запрос и повтор не называются гарантированно холодным/прогретым:
исходная загрузка и кеш могут отличаться. После проверки API/модели и создания
каталога сбой серии сохраняет частичный отчёт с complete=false; скрытого повтора
нет. Ошибка /api/tags, /api/ps, отсутствие модели или невозможность создать
каталог завершают подготовку до появления report.json. Повтор1 даёт лишь три наблюдения, этого
недостаточно для надёжных процентилей задержки.

Даже6/6 не доказывает умение строить, выбирать координаты, управлять камерой,
проходить новые сцены или выполнять длинный план. Следующий этап после реального
замера — ограниченный исполнитель с состоянием/остановкой существующего канала,
проверкой результата и обычными правилами строительства. Основной игровой путь
и сохранность TEST24 после respawn/reload остаются открыты.
