# .237 — проверка отсутствия частей перед возвратом

19.10.2026 · [English](CHECKPOINT_237.md)

Отдельные `AbsenceExpectation`/`AbsenceEvidence` проверяют отсутствие набора operation ID во всех mapped chunks одного сохранённого world41/42. Сканирование общее с прежним положительным reader, но типы доказательств не взаимозаменяемы. Запрос неизменяем и ограничен50000 ID. Любая целевая метка, неверный тип/повреждённая метка, пропущенный/оборванный файл, неверный мир, превышение бюджета или отмена запрещают результат.

Файловый адаптер удерживает проверенные файлы поколения; game-thread оболочка проверяет Local host, тот же мир, SaveSystem generation и custody до/после worker. Worker не вызывает игровые API. DB2 проверяется только по заголовку: это не полная проверка native-загрузки мира.

10001 запись прочитана одним проходом,773912 выделенных байт на .NET10 CPU; это не замер Mono/Valheim. Native карта может содержать меньше фактических mapped entries, чем объявленный total: size-changed entries штатно пропускаются при записи. Reader сохраняет эту совместимость и отказывает, если реально mapped файл отсутствует.

**Ограничение:** production caller оплаченной отмены ещё не подключён. Доказательство отсутствия само по себе не разрешает возврат: деталь могла разрушиться и выдать ресурсы раньше. Нужны сохраняемое намерение, доказанная собственность, контролируемое удаление без drops и отдельный протокол выдачи/подбора. `CancelUnpaid` сохраняет запрет при оплаченных receipt.
