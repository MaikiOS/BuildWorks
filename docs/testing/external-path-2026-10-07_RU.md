## Воспроизводимая автоматическая проверка

Из корня BuildWorks: `./scripts/Capture-UiWorkbench.ps1` в PowerShell 7.
Нужны установленный Unity 6000.0.61f1, текущие локальные игровые asset bundles и закреплённый ZIP.
Испытание отказывает при другом хеше ZIP/файла и не перезаписывает изменённую исходную копию.

Используются настоящий reviewed import и фоновый каталог, реальные prefab scale/меши,
BlueprintEditorController и мировой renderer. Первая деталь сдвигается на +0.25 по X;
добавляется независимая опора `(1.25,-0.25,0.5)`, yaw37; она назначается опорой размещения.
После сохранения и открытия с диска сравниваются все позиции, повороты, масштабы, исходные строки
и авторская поза опоры. После экспорта нашего JSON и повторного чтения сравнение повторяется.
Мировой план ставит опору в `(25,4,-15)`, yaw73: проверяются матрицы каждого объекта и наличие
видимой непустой геометрии каждой детали. Общего уменьшения постройки нет.

Финальный результат: 252 UI-снимка плюс два изображения реальных построек.
`wood_roof` имеет исходный scale `(1.00000048,1,1.00000048)`; используется нормализация
относительно настоящего prefab, а не предположение о единичном масштабе.
Выступающие балки Forest Hut присутствуют и в исходной миниатюре; это не исправлялось как ошибка.
Камера/освещение отличаются от миниатюры, пиксельное совпадение не заявляется.

Доказательства: `artifacts/external-path-2026-10-07/verification.json`, `actual-divider-check.txt`,
`unity-status.json`, два `real-*-world-preview.png` и хеши исходников испытания.
Ожидается `PASS actual external pipeline;`; отсутствие токена, `BLOCKED/FAILED`, пустая геометрия,
изменение поз/масштаба/исходника/опоры означают провал, даже если появилась миниатюра.

## Следующая граница: настоящее строительство

Не проверены native construction, затраты, устойчивость, сохранение/перезагрузка мира,
отмена/частичный сбой в игре и сеть. Disk/editor reopen не является world reload.
Admin restoration ещё не реализован, отдельная успешная проверка этого режима невозможна.

Готового игрового survival-стенда пока нет. Пользователю не предлагается вручную собирать
материалы, открывать рецепты или строить подготовительные объекты. До выдачи ручного сценария
нужны отдельные тестовые мир/персонаж, автоматически подготовленные ресурсы/молоток/станция
и фиксация обычного режима без no-cost/debug обхода. Стоимость вычисляется из native recipes,
а не из описания внешнего файла. Следом — точный протокол кнопок/исходного состояния/ошибок
для обоих файлов, отмены и повторного входа; host/remote client проверяются отдельно.
Запуск Valheim и создание сохранений требуют явного разрешения по AGENTS.md.
Native управление CUA в этой сессии недоступно; Workbench не подменяет наблюдение в игре.

### Проверенные зависимости автоматической подготовки

Read-only исследование установленного host подтвердило public `Inventory.AddItem(GameObject,int)`,
`Player.AddKnownItem(ItemData)` и `Player.AddKnownStation(CraftingStation)`.
AddKnownItem обновляет native рецепты; прямую запись в `m_knownRecipes` делать не нужно.
AddItem ограничивает одну выдачу `m_maxStackSize`: выдавать порциями с проверкой реального count,
не считать bool доказательством полного количества. Станцию нужно физически подготовить:
одной записи о знании недостаточно для `CraftingStation.HaveBuildStationInRange`.

`HammerBlueprintPieceRegistry.Resources` использует native `Piece.m_resources/GetAmount(1)`,
но сначала требует открытых деталей через `TryResolveBlueprintPieces/TryResolveBuildPiece`.
Для нового персонажа это bootstrap-блокер: подготовка читает prefab напрямую по закреплённым
исходникам, затем открывает знания native API и перепроверяет обычный путь. NoCost/debug не включать.

До любой выдачи нужны: закрытый local server без connected peers, точные world name/UID и
character filename/player ID, оба `FileSource.Local`, разрешённый фактический save root,
отсутствие debug/NoCost/NoBuildCost/NoCraftCost/NoWorkbench, хеши исходников и одноразовый receipt.
Нельзя повторить выдачу после частичного сбоя; сначала сохраняется факт начала попытки.
Старый `TryRunArmedSkyCleanup` для этого не используется.

`Utils.GetSaveDataPath(FileHelpers.FileSource.Local)` и `Utils.SetSaveDataPath(string)` существуют.
Однако `-savedir` найден только в `FejdStartup.ParseServerArguments`, без найденных вызовов parser
в клиентском assembly_valheim, assembly_guiutils и Assembly-CSharp. Это не доказательство работы CLI.
Будущий стенд должен проверить фактический канонический root до мутаций и отказать при несовпадении.
Менять root после загрузки мира/персонажа нельзя. Автоматическая подготовка пока не внедрена.
