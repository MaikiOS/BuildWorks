[English](SERVER_LIBRARY_FOUNDATION.md) | **Русский**

## Граница полномочий

Core принимает **уже аутентифицированный principal**. Его нельзя читать из запроса. Resolver прав задаётся серверным адаптером; клиент не передаёт `isAdmin`. BlueprintServerAuthority связывает principal с текущим прямым соединением, проверяет серверный режим, готовность peer и совпадение socket, затем использует native `ZNet.IsAdmin`.

В текущей DLL Valheim `ZRoutedRpc.RPC_RoutedRPC` десериализует sender из payload, не использует входной ZRpc для его аутентификации. Поэтому routed sender UID не подходит для проверки административных прав. Native RPC_Kick/RPC_Ban используют socket.GetHostName → admin-list policy; это подтверждено чтением IL. Runtime регистрирует прямые typed ZRpc callbacks; существующий handshake Valheim не заменяется. Инертный тест не подтверждает живое соединение.

Серверные файлы — отдельные `<id>.bwserver.zip`, ровно `access.json` и `blueprint.buildworks.json`; формат metadata version1, ID/revision/access/publisher/editor/time/SHA. Временные файлы не входят в каталог. Portable-документ остаётся существующего формата: стоимость, права строительства, административное восстановление и world/network identity не меняются.

Пределы:512 записей,128 МиБ суммарных stored и unpacked bytes,100000 деталей суммарно;32 МиБ portable-документ и4096 bytes metadata. Предел распаковки проверяется до чтения члена ZIP; физический файл ограничен уже на открытом FileStream. Повреждение записи останавливает загрузку целиком; частично загруженный публичный кеш не публикуется. Внешнее изменение проверяется перед чтением/заменой/удалением; автоматическое слежение за ручными правками файлов не реализовано.

## Следующий рабочий срез

1. Подключить одинаковый сценарий каталога редактора/молотка: источник «Сервер», просмотр доступного списка, принятие личной копии; admin publication/access/update/delete с явным результатом и причиной отказа.
2. Проверить настоящий host+remote, отзыв прав, переподключение и restart. Только после этого отмечать игровую серверную поддержку. Личная передача между игроками требует отдельного принятия и сохранения ограничений происхождения.

## Подключённый транспорт

`BlueprintServerProtocol` v1 ограничивает кадр64 KiB, чанк60 KiB, страницу12 записей и документ32 MiB. Только доверенный адаптер определяет principal/роль; в запросах их нет. Endpoint ограничивает64 соединения, общую память передачи128 MiB, частоту, неактивность30 с; временные файлы/буферы освобождаются при отказе, отмене и разрыве. Результаты32 последних изменений на соединение допускают повтор получения ответа без повторной записи. Это не постоянный журнал повторов после рестарта: новая сессия отклоняет прежние пакеты, клиент автоматически публикацию не повторяет.

Хранилище находится в `config/BuildWorks/server/world_<UID>/`; пустое чтение каталог не создаёт. Runtime работает до раннего выхода плагина при отсутствии локального игрока. Обработчики регистрируются на готовом прямом peer и удаляются при его потере/смене мира/выгрузке. Localhost проходит тот же endpoint с частным локальным токеном и проверкой фактического host. При смене мира незавершённая worker-очистка завершается до открытия нового endpoint.

PrepareRead/PreparePublish выполняют тяжёлое чтение/разбор/упаковку на worker без Unity API. CompleteRead/CommitPublish повторно проверяют текущие права, ID/revision и одноразовое владение подготовкой на host-thread. Commit ещё проверяет SHA старого/временного файла на host-thread; полностью свободным от файлового IO этот этап не объявляется. Сбой отправки ответа после commit не отменяет уже совершённую запись. Клиент владеет снимком публикации, проверяет ответ/ревизию/SHA и ограничивает hashing/send четырьмя чанками за кадр.

Нативный `ZPackage.Write(byte[])` добавляет длину: для нашего raw кадра используется проверенный конструктор `ZPackage(byte[])`. HostContract закрепляет это и порядок dedicated tick. До `GetArray` проверяется размер входного ZPackage. Глобальное выделение памяти внутри Valheim до callback этот адаптер не меняет.

Дальше: единый серверный интерфейс редактора/молотка, admin publication/access/update/delete, принятие отдельной личной копии с сохраняемым происхождением. Не использовать для происхождения transient placementImportId и не подделывать внешний SourceDocument. После этого — установка и настоящие host+remote/reconnect/restart проверки. Личная передача между игроками остаётся отдельным сценарием принятия.
