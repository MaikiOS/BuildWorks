# 313 — происхождение принятой личной копии, файловый срез

22.10.2026. Кандидат .278 не устанавливался; изменения включены в последующий .279.

Для требования13.7 добавлены пассивные данные происхождения: сервер/мир, отправитель,
получатель, offer/document ID, SHA256 и версия входного документа. Не более16 записей;
неоднозначные повторения, неверные ID/hash/поля и превышение лимита отклоняются до
изменения документа. Это описание происхождения, не доказательство личности или права.

Native26 и portable15 сохраняют записи через открытие, копирование, merge, Undo/Redo,
Save As, update и импорт. Старые документы читаются без новых полей; новые поля под
старыми заголовками отклоняются даже как null/пустой массив. Старые бинарники не
обязаны читать native26/portable15. QA-каталог этим срезом не мигрировался.

`TrySaveAcceptedPeerCopy` сверяет точные входные байты/hash/ID/версию и сохраняет
новую личную копию с новым ID. Метод не является сетевым принятием или защитой от
повторной доставки. Для будущего обмена ещё нужны server receipt, авторизация,
идемпотентность, выбор получателя, подтверждение в UI и host/remote/reconnect.
Сторонний экспорт предупреждает о потере непредставимого происхождения.
