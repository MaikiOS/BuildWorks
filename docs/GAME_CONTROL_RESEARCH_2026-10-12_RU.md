# Быстрое управление Valheim: исследование 2026-10-12

**Продолжение:** Qwen3.5/LFM3B скачаны и измерены, локальный pilot подготовлен,
QA .164 установлена. [Текущий протокол](LOCAL_QA_AGENT_2026-10-12_RU.md).
Ниже история исследования до установки.

Запрос Ostrix: найти инструменты для быстрого управления игрой, вместо ожидания
ответа модели после каждого движения. Исследование документации и исходников;
ничего не установлено, игра не запускалась, скорость на этом ПК не измерена.

| Инструмент | Подтверждено источником | Граница |
| --- | --- | --- |
| [NitroGen](https://github.com/MineDojo/NitroGen) | Модель видит изображение и выдаёт действия геймпада для Windows-игр | Видит последний кадр, авторы исключают длинное планирование и прохождение целиком. Работа в Valheim/BuildWorks не подтверждена |
| [Airtest](https://github.com/AirtestProject/Airtest) | Локальные сценарии проверки игрового интерфейса по изображениям; Windows поддерживается | Сценарии нужно написать; это не самостоятельный игрок |
| [DXcam](https://github.com/ra1nty/DXcam) | Непрерывный захват кадров Windows с буфером последних кадров | Ускоряет получение изображения, но не принятие решений моделью. Чужой FPS не является измерением нашего ПК |
| [PyDirectInput](https://github.com/learncodebygaming/pydirectinput) | Клавиши через scan codes/SendInput и относительное движение мыши | Только ввод; без распознавания сцены и планирования. Valheim не проверен |

Особенно важен [исходник среды NitroGen](https://raw.githubusercontent.com/MineDojo/NitroGen/main/nitrogen/game_env.py):
GamepadEnv создаёт xspeedhack.Client, perform_action вызывает unpause/pause,
которые выставляют скорость 1/0. В штатном варианте это вмешивается в ход времени;
он не подходит без изменения среды для доказательства обычной физики, стройки
и сетевого поведения BuildWorks. Частота выдачи действий не доказывает такую же
частоту независимых решений модели.

[Poco Unity SDK](https://github.com/AirtestProject/Poco-SDK/tree/master/Unity3D)
требует добавить файлы в Unity-проект и PocoManager.cs на GameObject. Готовая
совместимость с собранным Valheim через BepInEx не установлена. AltTester тоже
требует инструментирования игры; это не доказанный готовый переход.

Поиск доступных плагинов не дал подходящего игрового контроллера. Neuronto
вернул UE5-gameplay-mcp, LÖVE2D MCP и обычную автоматизацию рабочего стола;
готовая совместимость с Valheim не подтверждена. Заявления каталогов не
приняты за проверенную работоспособность.

## Рекомендация для BuildWorks

Сохранить существующий изолированный QA-канал и добавить локальное выполнение
ограниченного сценария с обратной связью: наблюдать состояние, выполнять ввод,
проверять условие, продолжать без обращения к модели после каждого шага.
Airtest подходит для изображений/проверок UI; DXcam и относительный SendInput
имеют смысл только при измеренном недостатке существующего захвата/ввода.
Новый сервер MCP мыши сам по себе не устранит ожидание между ответами модели.

В текущем BuildWorksQaControl ввод исполняется в процессе игры, но наблюдение
публикует снимок PNG и результат команды. Доля затрат ReadPixels/EncodePNG,
обмена файлами и ожидания модели пока не измерена; причина конкретной задержки
не объявляется установленной только по чтению кода.

Первый проверяемый опыт: один безопасный сценарий поворота камеры/выбора молотка
и UI в прежнем QA-мире. Измерить полное время и задержку наблюдения, подтвердить
остановку, освобождение клавиш, отсутствие действий при потере фокуса/смерти,
отсутствие изменения игрового времени. Затем использовать тот же исполнитель
для новой серии snap на .163. Строительство, стоимость и права остаются штатными.
Разработка исполнителя и установка зависимостей этим исследованием не выполнены.

## Дополнение: проекты со скриншота и локальная модель

По следующему сообщению Ostrix проверены дополнительные кандидаты. Предыдущий
поиск был неполным: существуют специальные мосты управления Valheim.

- [Gamini](https://github.com/yumozi/gamini) действительно содержит цикл захвата
  видео, решения модели и последовательности действий. В
  [game_loop.py](https://github.com/yumozi/gamini/blob/main/backend/game_loop.py)
  запись идёт параллельно ожиданию ответа и выполнению. По умолчанию окно видео
  1,5с/5 FPS; это частота изображения, не решений. В
  [gemini_client.py](https://github.com/yumozi/gamini/blob/main/backend/gemini_client.py)
  вызывается Google Gemini API с видео MP4; Ollama не является готовой настройкой.
  Нужны отдельный клиент и преобразование наблюдений. Windows backend поддерживает
  относительное движение. Наличие F12 не доказывает освобождение всех удержанных
  клавиш: в прочитанных finally цикла освобождение ввода отсутствует; до запуска
  нужно проверить это отдельно.
- [Valheim AI Agent](https://github.com/itenev/valheim-ai-agent): README ещё
  отмечает автономный цикл Pending, но текущий
  [valheim_agent.py](https://github.com/itenev/valheim-ai-agent/blob/main/agent/valheim_agent.py)
  уже вызывает planner.call_llm и bridge.send_action. Поэтому Pending в README
  нельзя считать доказательством отсутствия реализации. Установка документирована
  для Linux; Windows/runtime совместимость не проверена. В
  [ActionHandler.cs](https://github.com/itenev/valheim-ai-agent/blob/main/plugin/ActionHandler.cs)
  BUILD вызывает Player.PlacePiece напрямую, CRAFT вручную списывает ресурсы и
  добавляет предметы. Это не доказательство штатного пути молотка/BuildWorks.
- [ValAgentBridge](https://github.com/skatefast29/ValAgentBridge) — более предметный
  кандидат для QA модов: автор заявляет Windows/Unity6/BepInEx, состояние мира,
  ввод/навигацию, снимки/логи и JSON сценарии. Независимый read-only агент проверил
  README и сравнил исходный ValBridgeServer; совместимость не доказана. Штатный
  запуск требует GABS и его окружения, иначе мост не активен. Это расходится с
  текущим правилом запуска через Thunderstore Modded и требует отдельного решения,
  а не скрытой замены способа запуска. Raw README/часть исходников недоступны
  через web; прочитан GitHub README. Проект не установлен.

Живое read-only наблюдение 2026-10-12: RTX4090,24564MiB, занято2776MiB при
закрытой игре. Ollama PID8136; /api/tags подтвердил qwen3-vl:4b-instruct
(3295636231 байт),8b-instruct,2b/4b/8b/30b и другие модели. /api/ps пуст.
Первый GET в песочнице получил ошибку запрещённого сокета; повтор вне песочницы
успешен. Генерация/загрузка модели, скачивание и настройки не выполнялись.

Обновлённая рекомендация: первым измерить уже установленную **qwen3-vl:4b-instruct**
в Ollama на сохранённых QA-кадрах, без управления игрой. Qwen официально описывает
[распознавание интерфейса и computer-use](https://github.com/QwenLM/Qwen3-VL),
но это не подтверждает навык игры в Valheim. Измерять полный ответ до валидной
команды, качество координат/решения, холодный и прогретый запрос; скорость
генерации текста сама по себе не годится. Локальная модель устраняет сетевой
запрос, но делит GPU с игрой, поэтому ускорение не гарантировано.
После измерения подключать только ограниченные команды существующего QA-канала:
я задаю сценарий, локальная модель выбирает следующий шаг, локальный исполнитель
проверяет условия/срок/остановку. Стоимость, права и размещение остаются штатными.
Это выбранный кандидат и план опыта, не реализованный автономный игрок.

## Присланный обзор Local AI Gaming Agent

Проверен файл `D:/Downloads/Yandex/Local_AI_Gaming_Agent_for_Codex_RU.md` и его
ключевые первоисточники. Вложенное «Задание для Codex» рассмотрено как предложение,
а не разрешение создать отдельный универсальный проект или запустить вычисления.

- [Qwen3.5 4B в Ollama](https://ollama.com/library/qwen3.5) доступна с изображениями
  и инструментами. Рекомендация: кандидат единой модели зрения/решений, сравнивать
  с установленной Qwen3-VL 4B, не объявляя смену успешной до измерений.
- [LFM2.5-VL-3B](https://huggingface.co/LiquidAI/LFM2.5-VL-3B): приведённые шесть
  метрик совпадают с таблицей производителя. Они не являются игровым тестом.
  Производитель рекомендует короткие задачи и ограничивает применение к
  длительным сложным рассуждениям. Вторая модель — только после полезного замера.
- [GGUF](https://huggingface.co/LiquidAI/LFM2.5-VL-3B-GGUF) подтверждает Q4_K_M
  1,67ГБ и команды Ollama/Windows llama.cpp; размер файла не равен полной VRAM.
- [NVIDIA SDK](https://github.com/NVIDIA/game-agent-sdk/blob/main/docs/sphinx/source/introduction.md)
  подтверждает Windows10/11, driver570.65+, CUDA12.8+, Qwen3.5-4B-Q4_K_M и
  средства интеграции AI companions, не готовое управление Valheim. GitHub
  просмотр вернул Internal Error; исходный файл прочитан через raw URL.

Существующий QA-канал BuildWorks остаётся кандидатом исполнения: самостоятельный
локальный цикл должен выбирать короткие действия и проверять последствия без
запроса Codex после каждого движения. Он не должен подменять проверяемые молоток,
стоимость, привязки и размещение прямым созданием объектов. Первая игровая серия:
выбор чертежа, наблюдение призрака, отмена без списания. Это план, не выполненный
тест. Скачать/запустить модели Ostrix пока не разрешил; игра и ввод не запускались.
[Подготовленный сценарий замера](QA_VISION_PROBE_2026-10-12_RU.md) прошёл шесть CPU
тестов и независимое чтение PASSED/Ponytail Ship. Он проверяет только четыре
признака на трёх кадрах и ещё не измеряет координаты, выбор действий или автономность.
