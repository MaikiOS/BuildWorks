# Проверка импорта и редактора — 0.19.81

Это промежуточная сборка, не объявление полной поддержки чужих чертежей.
Проверки ниже не требуют прокачки, ресурсов, изменения настроек мира или строительства.
Нужен только молоток и открытое меню BuildWorks в тестовом профиле TerrainRamp-1.0-Test.
Не используй основной мир для проверки восстановления вещей.
Если редактор сообщает о недоступном рецепте, не открывай его специально:
«Проверить чертёж» → «Скопировать отчёт» и пропусти этот пример. Проверка доступности
рецептов персонажа пока остаётся; универсальный тестовый герой ещё не подготовлен.

## Где лежат подготовленные файлы

В игре: молоток → «Чертежи» → «Импорт файла» → «Папка BuildWorks» →
«Папка: test-fixtures». Путь вручную вводить не нужно.

Полный путь:

`C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\TerrainRamp-1.0-Test\BepInEx\config\BuildWorks\test-fixtures`

Там шесть отдельных файлов. Не импортируй их разом: пятый специально содержит
несуществующую деталь и должен быть отклонён. Исходные файлы не меняются.
Успешный импорт сохраняет отдельную копию нашего формата в папке `imports`.
В каталоге ищи названия `TEST 01`–`TEST 06`, категория `BW TEST`.

## Точные действия

1. **Длинный путь.** Открой папку test-fixtures. Путь должен занимать одну строку.
   Щёлкни поле, нажми End: должен быть виден конец `test-fixtures`; Home показывает
   начало. Стрелками можно прочитать весь путь. «Закрыть» находится вверху справа.
   Повтори в редакторе: каталог → «Чертежи» → «Импорт».

2. **Обычная конвертация.** Выбери `01-walls.blueprint` → «Импорт файла» →
   подтверждение импорта. Здесь нет вещей, поэтому переключатели содержимого
   неактивны. После успешного сообщения закрой окно. Найди `TEST 01 Walls` →
   «Редактировать»: должны открыться две деревянные стены. Ничего строить не надо.

3. **Экспорт и обратное открытие.** В молотке выбери `TEST 01 Walls` →
   «Экспорт файла». Оставь предложенную папку `exports`, введи имя
   `QA81-walls-json`, выбери BuildWorks JSON → экспорт → подтверждение.
   Скопируй показанный путь или запомни имя. Затем «Импорт файла» →
   «Папка BuildWorks» → «Папка: exports» → `QA81-walls-json.buildworks.json`.
   Подтверди импорт и открой полученную копию в редакторе: всё ещё две стены.
   Повтори экспорт с другим именем `QA81-walls-zip` и форматом ZIP.
   Повторный экспорт с тем же именем должен сообщить об уже существующем файле,
   а не перезаписать его. Исходный чертёж остаётся на месте.

4. **Надпись.** Импортируй `02-sign.blueprint`, открой `TEST 02 Sign` →
   «Редактировать». Должны быть стена и табличка с текстом
   «BuildWorks: Привет, Ostrix!». Экспортируй под именем `QA81-sign`,
   импортируй результат из exports и проверь ту же надпись.
   Это проверка данных и редактора, не сохранения поставленной таблички в мире.

5. **Исправленная ошибка открытия.** Отдельно импортируй `03-opaque.blueprint`
   и `04-snap.blueprint`. Каждый должен открыться через «Редактировать» как две стены.
   Для каждого нажми в молотке «Проверить чертёж»: строка `Editor: OK` ожидаема,
   `World:` пока сообщает о неподдержанных данных/точках. Именно эта разница
   раньше ошибочно мешала открывать редактор. Не пытайся строить эти два примера.

6. **Нет нужной детали.** Попытайся импортировать `05-missing.blueprint`.
   Должен быть отказ с идентификатором `buildworks_test_missing_prefab`.
   Одна оставшаяся стена не должна появиться как успешно импортированная постройка.
   Это специально подготовленный отрицательный тест, не неисправный файл библиотеки.

7. **Лампа — диагностика, не подтверждённое исправление.** Импортируй
   `06-lamp.blueprint` → выбери `TEST 06 Lamp` → «Проверить чертёж» →
   «Скопировать отчёт» и пришли текст. Если лампа ещё не доступна персонажу,
   отчёт это покажет; не нужно ради теста открывать рецепт. Если редактор доступен,
   открой его и приложи снимок стены рядом с лампой. Повтори отчёт для большой
   лампы в исходном проблемном чертеже. Нужны масштабы зарегистрированного префаба,
   версии из молотка и множителя документа: отчёт собирает их без изменения модели.

8. **Любой недоступный чертёж.** Выбери его → «Проверить чертёж» →
   «Скопировать отчёт» → пришли текст. При числе деталей более 512 отказ пока
   ожидаемый: повышение лимита без проверки расхода памяти и времени не сделано.
   Миниатюра означает наличие картинки, а не успешную проверку строительства.

## Что сейчас не перекладываем на игрока

- Не просим создавать сундуки, добывать вещи, открывать рецепты и прокачивать героя.
- Проверка восстановления сундуков, креплений, отмены с возвратом ресурсов и клиента
  требует отдельной подготовленной испытательной площадки. Она в этой сборке не создана.
- Независимые галочки содержимого при импорте/экспорте уже проверяются автоматически,
  но такой выбор непосредственно перед размещением в мире ещё не реализован.
- Чужие непрочитанные данные сохраняются дословно в нашем файле как исходные сведения.
  Это не равно их восстановлению в игре. Блокировка остаётся, пока нет безопасного декодера.
- Для крупных чертежей, постоянных точек в мире, брони, свободных предметов и изменения
  миниатюр внешней библиотеки ещё нужна разработка.

## Как должны быть устроены следующие испытания

Рекомендация: отдельный тестовый мир и герой, два явных режима испытаний.
В режиме просмотра заранее готовы чертежи и объекты, не нужны рецепты и ресурсы.
В режиме проверки выживания — заранее известный запас ресурсов и предметов,
обычные правила списания, доступов и возврата; никакой бесплатной выдачи внутри
производственного кода размещения. Тесты должны показывать «до/после» и сохранять
машиночитаемый отчёт. До готовности этой площадки перечисленные проверки мира не
выдаются игроку как обязательные действия «создай всё самостоятельно».

Сейчас автоматизированы изолированный Unity и проверки кода/формата.
Доступный инструмент управления интерфейсом не управляет нативным окном Valheim;
самостоятельная проверка агентом внутри игры пока не выполнена.
