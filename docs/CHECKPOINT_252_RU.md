# QA .244 — сохранённые предметы возврата перед подбором

20.10.2026. Технический этап возврата по фактическому вкладу. Подбор, завершение оплаченной отмены и пользовательский интерфейс ещё не готовы.

## Что изменилось

Журнал `.bwpayout` связан с тем же RemovedSaved, миром, плательщиком и неизменными `.bwpart`. Он принимает ровно исходные PaidRows с точным количеством и свойствами, нормализуя только ячейку/экипировку для хранения на земле и добавляя собственную временную метку. До создания каждого native ItemDrop сохраняется Attempted; неоднозначная попытка никогда не повторяется автоматически. Наблюдения имеют уникальные native ID внутри одной загрузки. Это не постоянная идентичность после reload: ею служит отдельная метка записи.

Ранняя защита действует через оба Awake независимо от порядка компонентов; все вложенные кандидаты получают сохраняемую метку, а принята может быть только одна точная копия. Native SaveToZDO не может переписать защищённый предмет другим пакетом. Пока передача не завершена, запрещены подбор, употребление NPC, слияние, despawn, смена владельца, превращение в Piece и явное удаление. Проверка auto-stack использует тот же Physics overlap коллайдеров, что игра. После Start ещё раз проверяются actual ItemData и ZDO bytes.

Перед выдачей полностью читается сохранённый мир для отсутствия исходных оплаченных частей. После создания записывается save intent, сохраняются неизменный профиль и следующее поколение мира, затем снова проверяются отсутствие частей и каждый уникальный native itemData blob с владельцем. Только после этого журнал получает IssuedSaved. Предметы остаются защищёнными после reload. Оплаченная отмена через интерфейс пока не включена.

## Что дальше

Архитектор подтвердил native Player.Save: инвентарь и Player.m_customData входят в один снимок профиля. Следующий шаг — постоянная квитанция получения каждой записи, проверка её настоящего файла после сохранения, затем удаление прежнего sealed drop и доказательство отсутствия. Так старый world save не выдаст предмет второй раз после сохранённого получения. Нужен bounded разбор хвоста Player, точное внесение в пустую ячейку и защита от reentrant save; обычный Pickup целиком не подходит.

Не проверены/не готовы: controlled collection, terminal paid cancel/UI, crash injection, неопределённый RemovalIntent, каскадное разрушение зависимых частей, ordinary-neighbour auto-stack и nested-Awake injection в игре, отключение мода при pending custody, широкие специальные/mod-prefab и сеть. Последовательные полные сканы подходят двум текущим записям; тяжёлые возвраты требуют отдельного измерения/группировки. Shader/v11 и GPU-бюджет прежние; внешний вид дома этим этапом не подтверждён.
