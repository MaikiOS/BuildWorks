# .137 — перенос указателя при преобразовании

Сценарий: обычная гизма либо G/R/S с ограничением осью/плоскостью → край
вьювера → перенос к противоположному краю → продолжение того же преобразования.
Ctrl позволяет выйти к панелям, кнопки осей остаются штатными UI-кнопками.
Свободное наведение G на поверхность, точки привязки и Array layout сохраняют
обычную мышь: они выбирают конкретное место, а не продолжают transform delta.

`BlueprintEditorInput.cs` использует публичный WarpMousePositionCommand через
reflection в уже имеющемся Unity.InputSystem1.19. Это тот же путь, что
Mouse.WarpCursorPosition; здесь проверяется результат ExecuteCommand вместо
игнорирования результата. Требуются физическая native/enabled/added Mouse,
фокус, свободный курсор и обе экранные точки внутри игрового окна. Нет DLL,
мыши или поддержки команды — честный отказ и сохранённый числовой ввод.
Backend не включается принудительно, новый пакет/Win32 hooks не добавлены.

`BlueprintEditorController.cs` хранит логическое смещение мыши. До прихода
отложенного переноса не отправляет команду повторно и не меняет предпросмотр.
Подтверждение только в радиусе8px от запрошенной точки, с допуском на малое движение руки. Движение просто ближе к точке не считается переносом. После подтверждения компенсирует скачок, продолжая прежнюю операцию. Нет наблюдаемого
переноса250мс — отменяет предпросмотр. Esc/потеря фокуса отменяют; Enter либо
отпускание физической гизмы во время ожидания подтверждает последний допустимый
предпросмотр. Reset/cleanup очищают всё состояние. Cursor.lockState/visible
перенос не меняет. Стоимость, мир, формат и сетевые права не затронуты.

Регрессия воспроизведена до подключения контроллера: Scale pointer stops at
viewport edge instead of wrapping. Последующие исправления проверок:
Point3 сравнивать через Equals, после Undo получать новую запись; размеры
RenderTexture не равны Screen в пакетном Unity, реальная проверка окна живёт
в платформенном адаптере; движение на уже достигнутом минимуме не должно менять
масштаб; после Bind/Undo дерево требует кадр для обновления raycast-разметки.
Логи сохранены в artifacts/checkpoint-0.19.137. Финальный результат отдельно
в verification.json; незавершённый прогон не считать passed.

Существенная открытая проверка: существует ли Mouse.current в настоящем Valheim
и видит ли legacy Input.mousePosition результат команды Input System.
Доступность API/HostContract и подменённый физический ввод этого не доказывают.
При неподдерживаемом backend курсор не переносится; это ограничение, а не
реализация непрерывного движения в такой конфигурации.

[Unity1.19 Mouse](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.19/api/UnityEngine.InputSystem.Mouse.html),
[Unity cursor warping](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.19/manual/Mouse.html#cursor-warping).

Независимый обзор нашёл ложный ACK по сравнению расстояний: обычное движение на55% к противоположному краю считалось переносом. Predicate воспроизведён; исправлен на8px proximity. Регрессия контроллера проверяет pending/неизменный preview/одну команду после такого движения, затем точное прибытие. При быстром движении за допуск безопасный исход — отмена по таймауту, не скачок модели.
