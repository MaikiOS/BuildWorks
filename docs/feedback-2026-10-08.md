.106 fixes repeated external selection creating a new copy, shared thumbnail/editor layer 31,
overlapping inspector actions, and adds world-unavailable card markers. The existing editor already supports missing-prefab placeholders. World construction gates remain.
Library conversion uses immutable Unity scale snapshots on the main thread and runs conversion
in a worker. Prepared sources survive native metadata saves; stale worker results are rejected.
Native v16 adds a local placement-copy cache identity, cleared on document edits and restored
on failed writes. Portable v6 omits that local identity. Earlier native versions remain readable;
an older DLL needs the earlier library backup after v16 is written. Old duplicates are not deleted.

These are automated/build results, not new game acceptance. .106 is installed by the guarded script with Valheim closed; the DLL hash matches and all48 QA files plus the library stayed unchanged. The 64 m QA yard exists; the larger 192 m yard remains open.

The actual archive has 353 blueprints / 614663 piece rows; 188 exceed the editor's 512-piece limit.
Removing that cap before staged visual loading would worsen freezes. Thumbnail rendering/PNG
encoding also remains synchronous. Lava lamps occur in 72 files / 735 rows with scale near one.
PlanBuild records and restores absolute root localScale; existing relative-scale algebra alone
does not prove the current prefab's appearance. Native prefab/child bounds, ghost and reload
measurements are required before changing scale. Source files remain untouched.

Persistent planned construction is still design: collisionless, noninteractive visuals plus one
stake; hammer-gated actions; server-authoritative job and resource escrow; actual construction
after full funding and placement validation; exactly-once refund of supplied item properties on
cancel/crash/reload. No free repair, quality increase or copied network identities. Future terrain
preparation is a separate job phase, without implementing terrain integration now.

Trees/world prefabs without recipes remain design: deny ordinary placement unless the server
administrator explicitly assigns a prefab-specific cost; administrative placement requires server
authorization. Growth/destruction/drop state needs a supported-data contract. No client-provided
admin flag or price can authorize construction.

Next gates: .106 narrow catalog/editor QA; staged heavy-document loading and isolated test-cap
bypass; native lava-lamp/compound-rotation diagnosis; supported state/snap conversion; persistent
jobs and server-approved recipe-less world objects. Exact resource/refund, reload, admin and
multiplayer acceptance remain distinct from build and static checks.
