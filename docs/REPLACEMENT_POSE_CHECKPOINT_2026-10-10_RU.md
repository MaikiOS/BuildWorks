# .130 — замена в позиции и ориентации отсутствующей записи

Исходники 0.19.130, checkpoint `d28efc3`. Этап не установлен: в `TerrainRamp-1.0-Test` остаётся
QA 0.19.117. Valheim, миры, персонажи и сетевые проверки не запускались.

## Поведение

- При выборе отсутствующей записи вместе со своими доступными деталями/группой
  замена предварительно переносится к записи. Начало координат и полный поворот
  опорной детали совмещаются с целью; остальные перемещаются вместе с ней.
  Опора — первая запись замены в документе, её имя показано в подтверждении.
- При выборе только отсутствующей записи: «ЗАМЕНИТЬ ОТСУТСТВУЮЩУЮ» →
  «Открыть каталог» → доступная деталь или полный чертёж. Сразу показывается
  результат на месте записи; предварительно расставлять и заново выделять не нужно.
  Для чертежа опорой служит его основная деталь, иначе первая запись.
- Размеры и собственный масштаб prefab сохраняются. Размер отсутствующей модели
  не переносится на другую модель. Совпадение origin и ориентации не обещает
  совпадения неизвестных поверхностей, геометрического центра или габаритов.
- Окно подтверждения справа, сцена не затемняется; клики в сцену блокируются.
  «ОТМЕНА»/Esc возвращают прежний вид без изменения документа. «ПРИМЕНИТЬ»
  выполняет одну операцию; один Undo возвращает запись, прежние позы и иерархию.
- Скрытые части каталожного источника остаются скрытыми и не показываются в
  предпросмотре. Неполный источник замены отклоняется с объяснением. Обычное
  размещение через каталог сохраняет прежнее поведение.
- Источник не меняется; метаданные, относительный масштаб, надписи, материал,
  группы и происхождение новых деталей сохраняются. Свободные опоры и общие
  привязки существующего документа не перемещаются. Опоры/привязки вставляемого
  чертежа преобразуются вместе с ним. Ссылки на заменяемую основную деталь/центр
  перепривязываются; новые записи получают новые ID.

После новой проверенной QA-установки: Thunderstore → `TerrainRamp-1.0-Test` →
**Modded**, только тестовые персонаж/мир `BW_QA_43d3719a`.
Материалы, рецепты и строительство стенда для этой проверки редактора не нужны.

Файл:
`C:\Users\nfspr\AppData\Roaming\Thunderstore Mod Manager\DataFolder\Valheim\profiles\Default\BuildWorks\tests\fixtures\replacement\14-replace-missing.buildworks.json`.
Карточка **QA115 Replace Missing**: **QA missing target**, **QA own wall A**,
**QA own wall B**. Рамка намеренно синтетическая, это не восстановленная модель.

1. Импортировать файл с сохранением отсутствующей записи, открыть «РЕДАКТИРОВАТЬ».
   Начальное состояние: три записи. Выделить **QA missing target**, с Ctrl добавить
   обе стены. Нажать «ЗАМЕНИТЬ ОТСУТСТВУЮЩУЮ».
   Ожидается перенос выбранных стен к известной позиции/ориентации записи уже
   в предпросмотре; размеры/взаимная раскладка стен сохранены. Имя опоры указано.
2. «ОТМЕНА»: три записи, стены на прежних местах. Повторить → «ПРИМЕНИТЬ»:
   две стены в новой позе, группа «Замена», отсутствующей записи нет.
   Ctrl+Z возвращает исходные три записи и позы; Ctrl+Y повторяет замену.
3. Ctrl+Z, выделить только **QA missing target**. Кнопка замены → «Открыть каталог».
   В «Деталях» найти `woodwall` и выбрать стену. Ожидается сразу предпросмотр
   у записи без движения мышью по поверхности. «ОТМЕНА» не добавляет стену.
   Повторить → «ПРИМЕНИТЬ»: новая стена заменила запись, всего три детали.
   Один Ctrl+Z возвращает начальное состояние без дополнительной копии.
4. Для проверки целого чертежа можно использовать уже имеющуюся карточку
   **TEST 16 Supported XYZ Snap** из файла
   `tests\fixtures\player-exchange\16-supported-snap.blueprint` (полный путь от
   указанного выше корня BuildWorks). Выбрать её в каталоге замены, проверить
   предпросмотр и отмену. Саму ранее принятую стройку файла16 повторять не нужно.
5. Подтвердить выбранную замену → «СОХРАНИТЬ КАК» → **QA130 Replacement Pose**.
   Закрыть редактор и повторно открыть копию: поза/размеры/группа совпадают.

Ошибка: стены остаются в прежних местах до подтверждения; добавляется сдвиг к
полу; меняется собственный размер; после отмены остаётся призрак/новая запись;
Undo требует нескольких действий; повторное открытие меняет результат.
Совпадение рамки и поверхности другой модели само по себе не критерий ошибки.
