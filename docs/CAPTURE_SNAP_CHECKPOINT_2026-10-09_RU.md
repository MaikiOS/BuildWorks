# 0.19.122 — точный поиск дубликатов при захвате привязок

Проверенный этап исходников. Установленная QA остаётся0.19.117 в
TerrainRamp-1.0-Test. Все12 отказов внешнего импорта, включая4 больших набора
привязок, остаются открыты.

## Что изменено

При сохранении выделения мира `TrySaveWorldSelection` больше не сравнивает каждую
пользовательскую точку со всеми уже сохранёнными. Ограниченный Geometry-сборщик
`BlueprintSnapPointSet` ищет соседей по пространственным ячейкам.

Сохранены прежняя float-арифметика, строгое условие квадрата расстояния
`<0.00000001f`, первые исходные координаты и порядок. Близость не считается
транзитивной: точка, которую уже исключили, не удаляет следующую. Дубликат
принимается и при заполненном наборе; новая точка сверх предела или некорректные
координаты отказывают без изменения набора. Результат доступен только для чтения.
На экстремальных координатах остаётся точный ограниченный полный перебор.

**Предел обратного захвата512 пока прежний.** Отказ не сохраняет обрезанный
чертёж. Предел512 на одну мировую деталь, форматы native21/portable10, права,
предметы и объекты мира не изменены. Существующий сборщик внешних native-привязок
не подходит: у него double-арифметика, включённая граница и исключение общих
между деталями соединений — другая семантика.

- Unity:17125 реально преобразованных точек с поворотом и XYZ-масштабом совпали

## Следующая зависимость

По текущей сборке Valheim прочитан native IL (`native-snap-contract.log`) и получен
независимый обзор. Молоток сохраняет полный порядок дочерних `snappoint`.
Штатный ручной выбор использует точный индекс этого списка. Автоматический поиск
сравнивает каждую исходную точку с близкими точками мира через `Vector3.Distance`;
при равенстве остаются первые target/source. Просто сократить список означает
изменить выбор игрока.

Следующий шаг: измерить создание дочерних точек и штатный поиск, затем ускорить
только автоматический путь BuildWorks с сохранением ручных индексов, порядка и
native-сравнений. После этого согласовать отдельный общий предел чертежа через
parser/Store/Geometry/portable/захват и проверить полный цикл4 файлов. Этот этап
ещё не повышает пределы и не удаляет точки ради успешного импорта.

Установки, запуска Valheim, изменений saves и сетевой проверки не было.
Ручной сценарий Ostrix для установленной .117 остаётся действующим.
