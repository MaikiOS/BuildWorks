## Что не прошло

Две ограниченные фоновые пробы — обычная камера и автоматический RT — дали0camera/production renders при включённой камере3440×1440.11/11 и12/12успешных RPC не стали доказательством renderer/FPS. Оба probe штатно восстановили состояние; повторы этого метода прекращены. Astra рекомендовала обычный оконный запуск через тот же GABS, без рабочего ввода.

Первый оконный запуск с прежним shader получил `Fog input queue is full` до подключения кандидата; `AttachExisting` отказал с `A ready, wholly unpaid preserved project is required.` Этот общий отказ включает FogError и не доказывает изменение оплаты. Затем выполнен один штатный logout/reenter без сброса: кандидат включён сразу при загрузке, до готовности всех28частей.

В повторном оконном сценарии прошли31шага; шаг32не завершил следующий baseline-маршрут: `The game's main thread did not answer in time (loading screen or paused?). The action may still happen when the game catches up.` Отдельная cleanup-попытка и единственный штатный logout также не ответили. Новые команды/игровые повторы остановлены. После начала этого маршрута новых overflow/исключений/DXGI/TDR в логах нет. Deadlock, точный стек зависания и его единственная причина **не установлены**; перегрузка прежнего renderer остаётся гипотезой Astra. FPS после отказа не вычислялся.

**Завершение:** Ostrix отдельно разрешил аварийное завершение только QA-процесса67688; его выход подтверждён,3DLL моста восстановлены с SHA-проверкой, игровых/Unity-процессов0.97project SHA,4141обычный файл по составу/размеру/времени и8cfg по значениям прежние; содержимое обычных сохранений не хешировалось. Последний заход не имеет подтверждённого штатного save, итогового inventory и выполнения временного shader/camera cleanup до аварийного выхода. Первые два процесса завершены штатно; no-render probe cleanup подтверждён. Установленная DLL .264 прежняя. Первый post-kill guard вернул `QA process remains live`, восстановление DLL было отложено; следующая проверка подтвердила отсутствие PID перед Restore.
