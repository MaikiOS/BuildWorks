# QA0.19.142 — строительство пустого штатного контейнера

Исправлен воспроизведённый отказ всего чертежа: сохранённый пустой либо явно очищенный `valheim-container-v1` ошибочно направлялся в проверку крепления предмета. Теперь проверка, подбор предметов и завершение размещения используют общий признак необходимости передаваемого предмета.

Разрешён только обычный штатный Container на корне детали, с полностью прочитанными данными и пустой таблицей default loot. Непустой неочищенный архив, неизвестные контейнеры, вложенные/производные компоненты и prefab с default loot остаются запрещены этим путём. Default loot создаётся внутри native Awake; удалять его после создания означало бы менять живой инвентарь. Для таких prefab нужен отдельный проверенный сценарий создания.

Оригинальный архив не меняется; исправление не загружает, не очищает и не записывает живой инвентарь. Это не реализация восстановления содержимого всех хранилищ и не завершение I03/I05.

Проверки: сначала красная регрессия отказа пустого контейнера, затем normal/QA без ошибок и предупреждений, HostContract Steam25185596, localization961, изоляция, compiled QA control, protocol28, EditorBridge и Unity Workbench492. Независимые обзоры: PASSED и Ship. Исходный коммит `5fa37eef8f91bd90315aa6d1cb843161f6c2f1db`.

Установлено штатным Deploy-TestBuild только в TerrainRamp-1.0-Test. SHA обеих DLL совпадают;137 существующих config/import/save файлов сохранили содержимое, размер и точные UTC-даты. Квитанции: artifacts/checkpoint-0.19.142/verification.json и installation.json.

Valheim не запускался. Реальные размещение, расход ресурсов и перезагрузка этого случая ещё не проверены. QA-канал из .141 сохранён; его первый запуск описан в [QA_CONTROL_RU.md](QA_CONTROL_RU.md).
